后台操作需要相应管理权限。

## 查看待办

进入管理后台，从「收件箱」或「事项中心」打开详情。

- **待处理**：归网站管理员、正在等待处理的事项，默认先看等待最久的。
- **等待报告者**：已经请报告者补充材料的事项，不计入收件箱待办数。
- **发布者处理中**：仍归资源发布者处理的事项。管理员可以查看并介入，不必等到超时。

事项中心可按类型、状态筛选。搜索范围包括全部、编号、类型、游戏、资源、报告者和对话内容。宽屏下可点击表头排序，拖动列表与详情之间的分隔条调整宽度。

## 回复前确认是否需要对方补充

网站管理员负责的事项，默认勾选「回复后等待报告者补充」。需要材料时保留勾选；只是告知进展时，取消勾选，保持当前等待状态。

对仍归发布者的事项，该选项默认不勾选，发布者的 7 天处理时限照常计时；勾选后则改为等待报告者。管理员回复不算发布者的首次回应。

回复可附最多 3 张图，单张不超过 8 MB。结案、处置与提请说明只写文字，需要配图时先回复。

## 按问题类型处理

| 类型                                                   | 处理方式                                                                                                                                                           |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 资源与描述不符、链接失效、解压或运行问题、资源其他问题 | 先核对，需要修正时在资源管理完成修改后再结案；无法复现要写明核对情况，不在受理范围要写明理由                                                                       |
| 求资源或催更                                           | 资源卡片上提交的先由发布者处理，转交来的与其他资源问题一样核对；游戏反馈里提交的直接归网站管理员。已补充或已安排时选「已处理」，不打算补充时选「不采纳」并写明理由 |
| 资源发错条目                                           | 搜索正确游戏条目并移动资源，以「已移动」结案；报告有误时选「不成立」并说明原因                                                                                     |
| 条目资料有误、条目「其他」                             | 完成修改后选「已处理」；不采纳时写明理由，同一条目其他未结意见也应逐条核对                                                                                         |
| 站务反馈                                               | 完成请求后选「已处理」；不采纳或不在受理范围时说明理由                                                                                                             |
| 评论、评价、小喇叭违规举报                             | 核对原文，使用对应的删除、下架或恢复动作；举报不成立时写明理由。恢复被误判的小喇叭时，认定举报「不成立」并结案                                                     |
| 用户违规举报                                           | 举报成立时，由超级管理员先在用户管理完成处置，再确认「已完成处置」、填写说明并登记「已处理」；不成立时说明理由并结案                                               |

资源问题可选的结论见[《资源问题处理指南（资源发布者）》](/doc/notice/issue-publisher)。网站管理员以「不在受理范围」结案时写明理由即可，不要求附指南链接；发布者结案时仍须附上一篇。超时转交的资源问题应核对后按实际情况结案，不能用隐藏资源代替处理。被举报的内容已删除时，核实删除事实并写明说明，不重复执行删除。

## 复核与提请结案

**报告者申请复核**：阅读前两轮处理记录和复核理由，再给出结论。复核结案后，报告者不能再次重开或申请复核。

**原发布者提请结案**：核对提请的结论与说明。确认已处理可采纳；不采纳时回复原因，提请提示会随回复收起。

超时转交且从未重开过的事项，原发布者仍可直接结案；如果报告者重开，事项继续归网站管理员，原发布者此后只能提请。

多人同时处理时，如果提交提示问题已被他人处理或更新，请先刷新，再决定是否继续操作。

## 久未回应与目标删除

网站管理员负责的事项不会自动结案。等待报告者补充满 14 天后，可选择「开启者未回应」手动结束；仍在等待管理员处理的事项不能用这个理由结案。

资源删除不改变原发布者的参与身份，已有对话继续保留。目标已删除的事项仍可结案，但必须写说明；失效的目标跳转和资源操作不再可用。

## 处理骚扰与滥用

按[《问题反馈指南（反馈提交者）》](/doc/notice/issue)中的禁止行为核查原反馈和往来记录。正常误报、材料不足、合理重开或复核，不应仅因结论不被采纳而处罚。

含辱骂、威胁或隐私信息的对话可以隐藏。原文保留供管理员核查，也可取消隐藏；已经发出的通知摘要不会随之收回。

确认恶意滥用后，按情节警告、扣除萌萌点或封禁账号。扣分交由站长处理；封禁由有权限的管理员在用户管理执行。处理说明写清违规事实和处罚理由，事项结案本身不会扣分或封号。

举报材料只供核查，不要在公开页面或回复中泄露其他举报人的身份和说明。

## 旧记录

以前的反馈和举报不搬进新列表。旧记录与历史通知链接保留，尚未处理的旧反馈和旧举报继续从原入口处理。
