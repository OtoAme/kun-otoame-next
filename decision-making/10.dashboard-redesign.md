# 管理控制台前端重构：需求整理

状态：2026-10-28 需求已定稿，站长确认第 6.1 节全部事项；实施任务见第 7 节，尚未开始实施。配套的可交互原型是本地文件 `backup/dashboard-prototype.html`（git 已忽略，示例数据），是布局、宽度与信息密度的验收参照。本文的现状来自只读核查源码与运营层计划文档；生产实际使用情况未核实。

本文的「控制台」指 `/dashboard` 下的站方页面；「旧后台」指 `/admin` 下的 HeroUI 页面；「工作台」指 `/workspace` 与 `/issue`，属于用户侧，不在本次范围（Q1）。「管理员」指 `role = 3`，「超级管理员」指 `role >= 4`。

侧栏另有「旧版页面」分组，列出 15 个仍在旧后台的入口（`constants/dashboard.ts` 的 `DASHBOARD_LEGACY_LINKS`）。

### 1.2 宽屏下阅读效率低的原因

- 统计总览把所有数字做成同尺寸卡片，网格随容器宽度从 2 列增加到 5～6 列。屏幕变宽只是一行放更多张卡片，没有新增信息层次，也没有「先看哪里」的引导。
- 待审事项已用左右分栏（35% / 65%），是控制台里唯一利用宽屏的页面；工单、链接健康、小喇叭、会社合并等页面多为单列列表，宽屏下行被拉长、右侧留白，详情要跳页或开弹窗。
- 首页看不到工单、小喇叭待复核、会社合并建议、创作者申请等来源的待办，站长要逐页点进去才能知道全站积压。

### 1.3 已有约束（必须保留）

- 控制台使用 shadcn，样式与前台、旧后台隔离（[01 实施计划](./7-operations-layer/01-admin-foundation.md) 第 6.3 节）；站内嵌入的入口仍用 HeroUI（运营层重构约束）。
- 权限由接口判断，界面只决定是否显示入口。
- `/api/admin/stats`、`/api/admin/stats/sum` 保持超级管理员门槛，普通管理员首页不请求它们（01 第 6.10 节）。
- `/dashboard` 收到旧待审参数时转向 `/dashboard/inbox` 并保留全部参数（01 第 6.10 节）。
- 旧页退役按「先有替代、验收、再重定向」进行，重定向保留查询参数和详情 ID（[09 实施计划](./7-operations-layer/09-metrics-and-retirement.md) 第 6.2～6.4 节）。

## 2. 目标与非目标

### 2.1 目标

1. 站长打开 `/dashboard` 一屏内能回答：现在哪些事在等我、最早的待审是哪几件、站点规模与近期增长、最近谁做了什么管理操作。
2. 宽屏显示更多有用信息（更多分区、更多列、列表与详情并排），而不是把同一块内容拉长；手机能完成查看和常规处理。
3. 旧后台全部功能在控制台有替代，旧后台可以退役。
4. 全部控制台页面使用同一套页面骨架（第 3.5 节），新增页面直接套用。

### 2.2 非目标

- 不改业务规则、结算、通知与审计逻辑；迁移复用现有接口和服务。
- 不新增统计接口（Q3）：总览不画趋势图，待办队列不显示「最长等待」汇总。
- 不实现 09 的运营指标页（中位处理时长、自动处理占比、历史快照）。
- 不动前台和工作台的界面（Q1）。

## 3. 需求

### 3.1 R1 站长总览（`/dashboard`，布局 A「指挥台」，Q6）

总览按分区并排排列，屏幕越宽分区越多；窄屏按表中顺序纵向排列。

| 区域         | 内容                                                                                                               | 数据来源                                                       | 可见范围            |
| ------------ | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- | ------------------- |
| 顶部摘要     | 全部待处理、我今日已处理；超级管理员另见窗口内新注册与新资源                                                       | 收件箱计数；`/api/admin/stats`                                 | 管理员              |
| 待办队列     | 每个来源一行：图标、名称、待处理数、占比条，点一行进入。来源为收件箱六类、员工侧未结工单、创作者申请、会社合并建议 | 收件箱计数；其余来源读现有列表接口的总数，接口没有总数的不显示 | 管理员              |
| 最早的待审   | 收件箱中等待最久的若干件：来源、标题、提交人、已等待时长，点一项进入该项详情                                       | 现有 `/api/admin/inbox`，按等待时长排序                        | 管理员              |
| 站点规模     | 用户、条目、游戏资源、补丁资源、评论、评分、投稿、创作者总数                                                       | `/api/admin/stats/sum`                                         | 超级管理员          |
| 近期增长     | 1～60 天窗口内新增用户、最近登录、新增条目、资源、评论的合计，可切换窗口                                           | `/api/admin/stats`                                             | 超级管理员          |
| 站点状态     | 注册是否开放、域名重定向是否开启（Q8：暂不加其他项）                                                               | 站点设置读取，需在控制台提供                                   | 超级管理员          |
| 最近管理操作 | 最近 10 条管理日志，可进日志页                                                                                     | `/api/admin/log`                                               | 管理员（Q4 下调后） |

- 「最早的待审」使用的是收件箱已有的等待时长，不是新接口；它只覆盖收件箱六类，不代表工单、会社合并等其他来源。
- 数字尚未读取或读取失败时显示占位或错误与重试，不显示成 0（沿用 01 第 6.10 节）。
- 计数沿用现有 60 秒轮询，不新增第二套轮询。

### 3.2 R2 布局与响应式

断点按主内容区宽度（容器查询），不按整个屏幕，侧栏展开与收起时布局随之调整。原型可切换 390 / 768 / 1280 / 1440 / 1920 / 2560 六种设备宽度。信息密度采用原型的「舒适」档：正文 14px、表格行上下内边距 10px，与现有 shadcn 默认尺寸一致；不提供密度切换。

| 主内容宽度   | 总览                               | 列表 + 详情类（评论、评价、资源、创作者等） | 表格类（用户、日志等）   |
| ------------ | ---------------------------------- | ------------------------------------------- | ------------------------ |
| < 768px      | 单列                               | 卡片行；点一项进入详情页，返回保留位置      | 卡片行，只留主要字段     |
| 768～1023px  | 两列                               | 表格；详情为右侧抽屉                        | 表格，基本列             |
| 1024～1439px | 三列：待办 / 规模与增长 / 最早待审 | 表格与详情左右分栏                          | 增加次要列               |
| ≥ 1440px     | 四列：再加最近管理操作独立一列     | 左侧筛选栏 + 表格 + 详情                    | 显示全部列，另加统计侧栏 |

- 长文本限制行宽（约 40 个汉字宽），表格在宽屏增加列而不是拉长列。
- 不出现整页横向滚动；窄屏侧栏为抽屉，宽屏侧栏可收起为图标栏。
- 主内容超过 1920px（如 2560 屏）时，内容区限宽 1920px 并居中，各页面布局与 1920 宽度相同。
- 深浅色继续与前台共用偏好。

### 3.3 R3 旧后台功能迁移

见第 4 节逐页清单。每页迁移要求：

- 覆盖旧页全部读取、搜索、筛选、分页、编辑、删除、批量操作和错误提示。
- 列表状态（筛选、搜索、页码、选中项）写进地址，可刷新、收藏与分享。
- 删除、封禁、群发邮件等不可撤销动作有确认框，取消不产生写入。
- 旧地址按 09 第 6.3 节重定向，时机见第 6.2 节。

### 3.4 R4 导航与图标

侧栏按工作类型分组，取代「旧版页面」分组：

- 总览
- 待处理：待审事项、工单中心、创作者申请
- 内容：游戏条目、下载资源、评论、评价、贴纸、已失效链接、会社合并、投稿历史、旧反馈与举报（归档）
- 社区：小喇叭、用户管理
- 站点：管理日志、站点设置、邮件群发
- 底部：发布游戏、返回前台、深浅色、当前账号

当前身份无权进入的页面不显示（Q5）。侧栏图标从 16px 放大到 20px；总览待办队列每个来源配 20px 图标与浅色底块，便于扫读（Q6）。

### 3.5 R5 页面骨架与通用交互

- 统一的页面骨架：标题栏（标题、刷新、主要动作）、筛选栏、列表、详情。
- 加载用骨架屏，空态说明「没有什么」与「下一步可做什么」。
- 键盘：列表上下切换、回车打开详情、Esc 关闭抽屉；焦点可见。
- 继续使用 `components/dashboard/ui` 的 shadcn 组件，缺少的组件（分页、表单、开关、徽标组等）按官方 shadcn 添加，不手写替代。

### 6.2 交付节奏（Q7，2026-10-28 已定）

一次开发完成，分两次发布：

1. 新控制台全部页面一次开发完成、一次上线，侧栏不再出现旧版入口。
2. 同一次上线不做旧地址重定向，旧后台继续可访问，作为新页面出问题时的退路。
3. 观察一周左右、确认日常工作不再需要旧后台后，再单独发布「旧地址重定向 + 删除旧页面」。

理由：本次同时包含约 15 个新页面和多项权限下调，若与旧页删除合在一起，任何一页出问题都没有可用的退路，回退也只能整体回退。拆出的第二次发布很小，只涉及重定向与删除，符合 09 第 6.2～6.4 节「先替代后退役」的约定。
