## 3. 数据模型

新表放在 `prisma/schema/help.prisma`，并在 user、patch、patch_resource 上补反向关系。

| 实体               | 字段与约束                                                                                                                                                                                                                                                                               |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `help_post`        | 作者（可空，注销置空）、分类、可空 `patch_id`（删除置空）、可空游戏名、资料链接数组（只在填游戏名时保存，最多 5 个 http(s) 链接）、可空 `resource_id`（删除置空）、标题、正文、`open/solved`、`accepted_answer_id`、`rewarded_answer_id`、隐藏标记、删除时间、发布请求键、创建／更新时间 |
| `help_answer`      | 父帖、作者（可空）、正文、隐藏标记、删除时间、请求键、创建／更新时间                                                                                                                                                                                                                     |
| `help_reply`       | 所属回答、作者（可空）、被回复的用户（可空，只保留回答者或已在楼里回复过的人）、纯文字正文（≤ 1000 字）、隐藏标记、删除时间、请求键、创建／更新时间                                                                                                                                      |
| `help_answer_vote` | 回答＋用户唯一，禁止投自己                                                                                                                                                                                                                                                               |
| `help_follow`      | 帖＋用户唯一，即「关注」，排除提问者                                                                                                                                                                                                                                                     |
| `help_daily_quota` | 用户＋上海日期复合主键；发帖次数、获奖次数                                                                                                                                                                                                                                               |

约束：

- `patch_id` 与游戏名至多填一个；分类为固定枚举，服务器校验。
- 发帖按作者＋请求键唯一，回答同理；重放返回原结果。
- `accepted_answer_id` 可改写或清空，必须指向同帖、未删除、未隐藏、非提问者的回答。`rewarded_answer_id` 只能从空写入一次，写入后不再改变。
- 删除用删除时间做软删除，公开查询一律排除；不做物理删除，以便举报与账务追溯。
- 「有用」数、关注数按关系表计数，不另存冗余列。

## 4. 接口与事务

拟新增 `app/api/help/`、`app/api/admin/help/`、`validations/help.ts`、`types/api/help.ts`；route 只负责鉴权和解析，业务逻辑放在 service。沿用项目的 CSRF 校验和中文错误；私有视图使用 `private, no-store`。

| 动作                 | 条件                                                 | 同事务结果                                                                                                                                                                                                     |
| -------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 发帖                 | 登录、可用余额 ≥ 5、当日发帖 < 3、关联对象存在且可见 | 建帖、日额加一、扣 5 点（键 `help:{postId}:post-fee`）                                                                                                                                                         |
| 编辑帖子／回答       | 作者本人、未删除                                     | 改正文、标题、关联；关联重新校验                                                                                                                                                                               |
| 删帖                 | 提问者、帖内没有他人未删除的回答                     | 锁父帖后重验，再软删除；不退费                                                                                                                                                                                 |
| 回答                 | 帖子未删除、未隐藏                                   | 插入回答；通知提问者                                                                                                                                                                                           |
| 删回答               | 作者本人、该回答不是当前采纳                         | 锁父帖后重验，再软删除                                                                                                                                                                                         |
| 回复／编辑、删除回复 | 回复时回答与帖子都未删除、未隐藏；编辑删除限作者本人 | 回复在父帖锁内插入；通知回答者和被回复的人（各一次，不通知自己）；删除为软删除，任何时候可删                                                                                                                   |
| 采纳／改选           | 提问者；目标为他人可见回答                           | 锁父帖，写 `accepted_answer_id` 与 `solved`；`rewarded_answer_id` 为空、双方注册满 7 天、回答者账号存在、回答者当日获奖 < 3 时，写 `rewarded_answer_id`、日额加一、发 3 点（键 `help:{postId}:answer-reward`） |
| 取消采纳             | 提问者                                               | 清空采纳，回到 `open`；不收回奖励                                                                                                                                                                              |
| 「有用」／「关注」   | 登录、非自己的内容                                   | 插入或删除关系行                                                                                                                                                                                               |
| 举报                 | 登录、非自己的内容                                   | 见第 5 节                                                                                                                                                                                                      |

锁序：先锁 help_post，再锁账户（按用户 ID 升序），最后锁日配额。删帖、删回答、采纳与新回答在父帖锁内串行，保证「没有他人回答才能删帖」「已采纳回答不能删」在并发时结果唯一。死锁或序列化冲突时整笔有界重试。

## 5. 举报治理

- 举报规则已登记在 [03 第 12.2 节「求助举报」](./03-case-system.md#122-后续模块占位登记)：帖子用 `content_violation × help`，回答用 `content_violation × help_answer`，回复用 `content_violation × help_reply`，归站方，权限为 `role >= 3`。一条事项就是一轮举报，结案后的新举报开新事项，旧举报自然不再计数，07 不存轮次字段。
- 一条事项中注册满 7 天的不同举报人达到 3 人时，03 在同一事务中调用 07 的隐藏原语，事项不结案。07 提供帖子、回答与回复的隐藏、恢复两个事务内原语，供 03 调用。
- 站方的结论：
  - 违规：`violation_hidden`，保持隐藏；如果目标尚未隐藏，同事务隐藏。
  - 不成立：`not_established`，恢复本事项造成的隐藏。
  - 只给结论：`handled`，用于目标未被隐藏或已被删除的情况。
- 举报者只能看到自己提交的说明和结论；被举报的作者不因此获得事项对话的阅读权限。
- 不设自动结案，不进入 03 的七天／十四天扫描。

## 6. 界面与入口

- 前台使用 HeroUI v2：`app/(site)/help/page.tsx`（列表）、`app/(site)/help/[id]/page.tsx`（详情）、`app/(site)/help/create/page.tsx`（发帖），组件放在 `components/help/`。
- 发帖页：分类、可选关联（条目搜索或游戏名）、相似求助、费用确认。
- 列表与详情用两栏布局（[HelpLayout](../../components/help/HelpLayout.tsx)，`lg` 断点起），右侧为[侧边栏](../../components/help/HelpSidebar.tsx)，数据来自 `GET /api/help/sidebar?status=&scope=`：分类计数按读者的可见性与列表当前的范围、状态筛选计算；「我发布的」「我关注的」各返回最近 3 条和总数。列表 `GET /api/help?scope=mine|followed` 需要登录，「我发布的」含本人被隐藏的帖子。
- 入口：顶部导航加「求助」，与「评论」「资源」并列（[constants/top-bar.ts](../../constants/top-bar.ts)）；首页 Hero 卡片下方的导航按钮（[constants/home.ts](../../constants/home.ts) 的 `homeNavigationItems`）把第一个「标签」换成「求助区」，指向 `/help`，按钮仍为三个，布局不变；标签页继续从顶部导航进入。
- 图片：`POST /api/help/image` 把图片转为 AVIF 存到对象存储 `help/<uid>/` 下，返回图床地址，编辑器插入 markdown 图片；与事项附图共用 `image-upload` 限频（Redis 故障时拒绝上传）。图片由正文引用，不登记、不消费，上传后未发布的对象不清理。服务端限制每条正文最多 6 张图片，列表取正文第一张 http(s) 图片为缩略图。
- 侧边栏跟随滚动：站点布局给 body 设了 `overflow-y: auto`，CSS `position: sticky` 在全站无效，[HelpLayout](../../components/help/HelpLayout.tsx) 只在三种静态位置之间切换（正常排布、`position: fixed` 停在顶部、贴住正文列末尾），滚动时不逐帧移动。
- 回答编辑器与评论区一致，支持图片和链接；标题、正文、回答长度上限参照评论区现有校验。
- 资源卡片和条目页：可以加一个「去求助区提问」链接，带上关联参数；不替换 D40 的事项入口。
- 资源卡片新增「复制分享链接」按钮，复制 `/{patchUniqueId}?tab=resources&resourceSection={section}&resourceId={id}`。这个深链格式与定位、高亮能力现已存在，见[资源标签页](../../components/patch/resource/Tabs.tsx)，只缺复制按钮；按钮放在资源卡片上，所有访客都能用，不只限求助区。
- 回答正文的链接沿用评论区的 `sanitizeUserHref` 安全规则，不做网盘域名拦截。服务端识别指向本站资源深链的链接，渲染为资源卡片标题；卡片不可见或已删除时，按普通链接文字显示。回答框常驻发布资源提示，并跳转到关联条目的资源发布页（PM 版第 3 节）。
- 后台使用 shadcn：举报复用现有事项举报队列，加上帖子／回答的预览与隐藏、恢复动作；所有动作都要二次确认。不新建待回答收件箱。
- 缓存：发帖、回答、采纳、删除、隐藏或恢复后，让对应的详情、列表、相似求助和首页聚合失效；私有视图不进公开缓存。
- 首页（M07-5）：
  - 「最新求助」按创建时间排序，未解决且没有他人回答的帖子优先。
  - 「最新评论」取游戏条目评论，同一条目只取最新一条。
  - 两者都只收作者注册满 3 天的内容，并经过同样的可见性过滤。
  - 实际启用新的首页 payload 时，同步缓存版本和所有读取方。

## 7. 迁移、上线与回退

- 只新建表，不回填历史数据。先只读 preflight，再审阅 SQL，然后执行 sync、postflight 和 schema guard；生产环境不使用 `prisma db push`。
- 上线顺序：隔离环境建表 → 后端与页面 → E07-01～04 → 上线包审阅 → 由站长部署。首页 UI 另批。
- 回退：先关闭发帖入口；已发帖子保持只读可见，已发奖励不回滚，表不删除。
- 上线后，按 PM 版第 8 节改 `posts/notice` 四篇里的提示，这部分作为单独的文档提交。

## 8. 测试与实验

E07-01～04 的判据见 PM 版第 9 节，都没有执行。先写 Vitest 单元测试和接口测试；再用独立的 PostgreSQL 与 Redis 和合成用户，验证真实事务与并发：采纳、改选、取消与删回答交错，删帖与新回答交错，重复发帖。最后在独立源码目录做生产构建，跑浏览器 E2E（桌面和 390px）。S3、邮件和外部请求用替身。证据记录代码 SHA、命令、通过与失败数、余额与账务明细对照；环境缺失就记为未通过。

## 9. 非目标

- 不新增依赖、版主体系、多层嵌套回复、全文搜索扩展或通用平台；回复只有回答下的一层。
