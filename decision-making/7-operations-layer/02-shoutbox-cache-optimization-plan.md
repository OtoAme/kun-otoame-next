# 小喇叭缓存与加载优化计划

## 1. 目标与执行边界

依据 [02 实施计划](./02-shoutbox.md)，补齐公共原始数据缓存，减少登录及偏好请求重复查库、重新挂载加载和隐藏页面刷新，并改善短暂故障时的展示。

本方案于 2026-09-13 经同一 mclaude Fable 会话完成三轮审阅及末轮整改核对，工具报告模型为 `claude-fable-5-1[1m]`、力度为 `max`。计划审阅无遗留严重或重要问题；实现与验收另行记录，不以方案通过代替代码验收。

- 保留首页 15 条、分页 20 条、游戏关联条显示 3 条；基础时长为首页／全站／横幅 60 秒、游戏作用域 300 秒。
- 刷新失败保留普通旧消息，首次失败可重试；官方置顶和横幅仍受真实时间边界约束，生效后的官方消息可作为公开历史保留。
- A 为服务端缓存，优先独立验收；B 为浏览器缓存与体验，完成后整体联调。两批均须完成。
- 不增加依赖、数据库表、推送、定时任务、预热或监控平台，不修改首页静态渲染、Cloudflare 配置、连接池和公共 Redis 基础设施。
- 本轮不自动提交、推送或部署，不进行真实高并发压测或数据库迁移。

## 2. 批次 A：服务端缓存与接口

### A1. 公共原始数据

首页、全站分页和游戏分页的所有请求均通过现有 `getOrSet`，取消 HTTP 个性化判定对内部 Redis 的限制。Redis 缓存原始载荷，返回前逐请求处理关联游戏的分级／屏蔽偏好，不改变消息本身的公开历史规则。

横幅先改为缓存原始消息及时间字段，再开放共享，两项同批交付；升级缓存键版本隔离旧 DTO，处理 JSON 缓存日期还原。个性化 HTTP 仍为 `private, no-store`；匿名 `s-maxage` 不超过 30 秒及剩余有效期，不提供过期缓存。

每次实际构建使用当前时刻；读取结束若跨过有效边界，最多重建两次，重建也经过请求合并。

### A2. 游戏时间边界

游戏作用域只查询本游戏下一条公开官方消息的生效时间，不再查询全站置顶与横幅的到期时间。普通消息和已生效官方消息不随 `effective_to` 从公开历史中删除；游戏列表到达边界时取新，不整体清空已有历史。排序、总数和页长不变。

### A3. 修订号与故障合并

在小喇叭缓存模块内使用一个专属 Redis 修订号，其键独立于 `shoutbox:*` 清理范围；数据键包含修订号，现有缓存锁随数据键隔离。

公开可见性写提交后，等待修订号递增尝试结束，再执行缓存清理及 Cloudflare purge，最后返回写接口响应。递增失败不回滚业务，继续独立尝试清理并记录错误。写入前开始的查询只能填充旧修订号数据，后续新请求不再使用它；已开始的读允许返回其当时快照，不扩展为全站强一致。

读取修订号失败时，不使用持久缓存。在小喇叭模块内用局部 Map 按展示类型／游戏／页码合并在途 Promise，完成后释放，不保存结果、不继续等待 Redis 锁。降级只保证同进程合并，不承诺 Redis 故障期间的跨实例合并。

### A4. 读取失败契约

| 情况 | 响应 |
| --- | --- |
| 正常读取，包括空列表及没有横幅 | `200`，保留现有成功响应字段 |
| 数据库或偏好读取失败，或有限重建后仍无有效载荷 | `503`，JSON 通用错误字符串，`private, no-store` |
| 读取暂时不可用 | `Retry-After: 60`；游戏作用域为 `300` |

Service 使用内部可识别的读取失败错误，由接口转换响应，不暴露底层详情。偏好读取失败不得回退为未处理偏好的数据。既有输入校验契约及 `/shoutbox` 服务端首屏异常兜底保留。

## 3. 批次 B：浏览器缓存、SSR 与展示

### B1. 范围与上下文

使用已安装的 TanStack Query v5，覆盖首页、游戏关联条、全站／游戏分页以及前台／Dashboard 横幅。个人记录和后台管理列表保留取数方式，只补充成功写入后的公共缓存失效通知。

两套根布局各持有稳定的客户端 QueryClient，SSR 每个请求独立，禁止跨 SSR 请求共享实例；服务端使用无限 `gcTime`，避免定时器继续保留已结束请求的缓存，浏览器无消费者缓存保留 5 分钟。只共享纯数据代码，保持 HeroUI v2 与 shadcn 隔离。

查询键包含展示类型、游戏、页码、用户 ID、实际分级偏好和排序去重的屏蔽标签，不持久化到 localStorage／IndexedDB；现有横幅关闭记录保留。登录、退出、账号或偏好变化时取消并清理旧作用域，旧响应不得进入当前展示。

### B2. 唯一请求入口

Query 负责响应式结果缓存和在途合并；网络统一经过小喇叭的薄刷新入口。固定选项：

```ts
enabled: false
retry: false
retryOnMount: false
refetchOnMount: false
refetchOnWindowFocus: false
refetchOnReconnect: false
networkMode: 'always'
```

不配置 `refetchInterval`。入口使用 `queryClient.fetchQuery`，显式 `staleTime: 0`，调用前统一检查是否需要取数，不通过切换 `enabled` 驱动请求。

- queryFn 将 `kunFetchGet` 的所有字符串错误转为异常，防止 503／校验错误成为成功缓存；最小校验成功对象及时间字段，单次 GET 超时 10 秒，不改共享 fetch 包装器。
- 隐藏页面不发起新的自动 GET，涵盖首次挂载、退避、重连及写后失效；已发请求可以结束。
- 恢复可见、期限到期和重试计时走同一入口，同 key 合并取数。
- 自动失败退避为 60／300 秒，按该 key 最近失败时间计算；重新挂载或反复切换可见性不能重置、绕过退避。
- 可见页面手动重试及写成功即时刷新可以跳过冷却；隐藏期间写入只标失效，恢复遵守统一规则。

### B3. 新鲜度与展示边界

新鲜度以绝对 `validUntil` 为准；observer 的 `staleTime` 为 `Math.max(0, validUntilMs - query.state.dataUpdatedAt)`，无数据或非法时间返回 0。调用前仍直接检查绝对期限和失效状态，不能从重新接收或显示时刻延长整段 TTL。合法空列表及 `banner: null` 同样复用有效期。

“到达即过期”仅指网络成功响应的 `validUntil` 不晚于该次接收时刻；这时从接收时刻退避 60／300 秒，避免立即循环。自然到期不能被当作到达过期，SSR 初始数据变旧按需补取。

真实边界清理只在共享展示投影中隐藏不确定的置顶／到期横幅，不调用 `setQueryData` 修改缓存，避免改变接收时刻、错误状态或失败冷却。缓存保留原始成功响应；定时及恢复可见触发展示重算、独立调度取新。保留 `visibilityUntil`、横幅自身到期时间、超长计时器及旧字段 fallback。游戏历史保留，未生效官方消息不可提前展示。

### B4. SSR 首屏

根 Provider 使用一次性 `clientReady` 标记，首次客户端 effect 后置 true，客户端路由切换不重置。

- 服务端及首次 hydration 按服务器真实上下文与 `initialData` 显示列表，不因持久化 store 默认 uid 0／默认分级拒绝 SSR，也不发起请求。
- SSR 上下文使用实际应用的 `visibilityWhere` 和当前请求用户 ID，用户 ID 从现有 SSR 鉴权 helper 获取，不传凭据；客户端期望分级按现有 API Cookie 规则计算，不改两套共享 helper。
- 客户端就绪后切实际 API 上下文；匹配且新鲜时不补 GET。
- 匿名非默认分级可能形成 SSR／API 差异：保留 SSR 首屏，就绪后补读一次；不能把 SSR 结果写入不匹配的 API key。
- 首次交接时同一用户可暂留消息文字并清除关联游戏信息，该临时展示不进入新 key，也不能用于跨账号或后续偏好切换。
- 客户端导航只给全新且上下文匹配的查询提供新鲜初始数据；已有查询，包括错误或失效状态，不能被旧 SSR 覆盖。初始数据只用于初始化，不在 effects 中重复回填，不引入 HydrationBoundary。

### B5. 加载、错误与写后更新

无初始数据时以 `status === 'pending'` 显示 HeroUI Spinner，涵盖未发请求的 pending／idle；不能用 `isLoading === false` 或 `!data` 判空。只有成功返回真实空载荷才显示“暂无”。首次错误提供重试；刷新错误保留普通旧消息和游戏历史，并给低干扰提示。横幅首次失败隐藏退避，已有横幅不越真实展示边界。

成功发布、编辑、自删、举报、官方发布或处置后，公共 helper 先等待 `cancelQueries` 取消写前结果，再用 `invalidateQueries({ refetchType: 'none' })` 标记公共查询失效。由于 observer 固定 disabled，不能依赖 `type: 'active'` 自动刷新；仅对当前作用域 `getObserversCount() > 0` 的查询，在 visible 时经统一入口取数。无消费者查询不主动请求，不新增事件总线、注册平台或跨标签页即时同步。复用同一查询键／选项工厂。

保留布局、分页位置、消息定位、确认弹窗和按消息 ID 关闭横幅的行为。

## 4. 验证与验收

| 项目 | 通过条件 |
