# 模块 10：链接检测、健康判定与公开结果（实施计划）

首批 04／05／10 的本地实现与技术验收状态见[首批验收记录](./12-first-batch-acceptance.md)；当前尚未提交、推送或生产部署。 固定上游加固、真实适配器、快照、公开双重事实和冲突处理已完成；首批仅夸克具备本站限定样本准入，其它网盘保持未知且不出站。生产主机、独立出口与部署窗口仍待确认。配对 [PM 版](./10-link-check-pm.md)。

参考：[kungal/kungal-link-live-checker](https://github.com/kungal/kungal-link-live-checker)，核查提交 `c74022f4dbbb7c8c39be7da15701763efa2ffffd`。优先自部署其 Go HTTP 服务，本站保留权限、版本、报告和健康流转的决定权。首批支持夸克；生产目标和独立出口仍待确认。

## 1. 目标与基线

已审样本能证明分享已删除、已取消或已过期时，直接将当前链接标为 broken 并折叠。机器 available 只说明检测端的观察，不能驳回用户报告；报告达阈值且与有效 available 冲突时进入 disputed，保留获取入口并人工复核。unknown 按 04 的用户证据继续处理；七天仅兜底普通 suspect，不处理机器冲突争议。

资源卡片逐链接同时显示最近机器结果及时间、近期用户反馈和当前处理状态。无检测记录、过期结果与失败均有明确显示。01～03 已上线的资源事项规则不因本模块改动。

## 2. 边界

- 检测结果经过 provider + status + reason/必要 providerCode 白名单映射；缺码、登录、验证码、限流、未知码及部分屏蔽无法判定时为 unknown。
- 使用已授权的用户报告、管理者手动检测、补链后检测三个触发；可靠失效处理一致。手动按钮须说明会更新状态，按既有确认规则执行。
- 查看卡片只读最新记录，不新增全站扫描、逐页自动检测、普通用户独立检测按钮或后台批量按钮。
- 新鲜可靠 broken 可结束机器冲突；available 不自动恢复已 broken 的链接，恢复仍是明确的管理动作。
- 健康只影响该链接的展示与折叠，资源 status、下载授权、获取配额和计数不由检测改写。

## 3. 术语与裁决优先级

| 条件                                                            | 判定                                                       |
| --------------------------------------------------------------- | ---------------------------------------------------------- |
| 请求无资格、目标不可见、链接归属或请求版本错误                  | 不出站，按现有 API 规则拒绝                                |
| 映射已通过样本审核、本次新鲜结果为 broken、写入时版本／轮次未变 | 当前链接直接 broken；状态条件更新胜出者留痕并通知一次      |
| available 与未达阈值反馈并存                                    | 保存两类事实，用户原权重保持                               |
| available 与达到阈值反馈并存，链接未被折叠                      | disputed，记录 machine/user 冲突来源，保留入口并交站方复核 |
| unknown 且达阈值，当前没有待复核机器冲突                        | 沿 04 转 suspect，进入七天处理规则                         |
| 原来已 disputed（机器冲突）或 broken，本次 available/unknown    | 更新机器快照；不因这次结果自动清除争议或恢复失效链接       |

冲突来源记录在事项事件／上下文中，由 W00 冻结具体键名并登记 03 实施计划 12.2。04 任务必须识别机器冲突，既不七天判坏，也不套用普通争议的新强证据自动判坏／三十天自动恢复。复核可用、复核失效、可靠机器失效或换地址各有明确出口，重复报告不能重置复核时钟或产生多个待办。

## 4. 数据与共享契约

W00 在 schema/SQL 派发前冻结以下最小数据合同；最终文件／字段由 04 数据作者单写，不由检测 worker 独立修改共享 schema。

- **最新机器快照**：建议为每个链接一行、外键删除随链接清理的结果记录，包含 link_id、地址版本、verdict、provider、安全原因码、真实 checkedAt、必要的时效信息。不存原始响应、完整 URL、提取码或账号信息，不建完整检测历史平台。
- **时序保护**：旧地址的回包不能写新版本快照；同版本较旧的观测不能覆盖较新的观测。并发完成顺序不等于观测顺序。
- **公开读 DTO**：沿资源读取返回当前版本的快照、时间与过期标记，以及当前地址版本／最近 72 小时已接收报告的去重人数（跨证据轮次保留）。人数表达反馈事实，不等于当前轮次的计权总分，不能反过来作阈值依据，不包含报告身份、正文或图片。
- **健康转换记录**：复用 04 链接历史和 03 结案事件所需的最小审计落点，保留原因、provider、checkedAt、对应版本和转换结果。W00 明确唯一性；机器结果不作为一个用户，也不参与用户权重求和。
- **机器冲突事实**：与未结争议同事务记录，后续任务与处理动作从同一事实读取。不能仅凭前端徽标或一个可能过期的 Redis 值决定是否跳过超时。

仅更新 available/unknown 快照时不刷新链接的内容更新时间；真实健康改变可按正常写入更新时间。写后刷新对应资源读取与页面缓存，不能只刷新后台。

## 5. 接口、权限、事务与幂等

### 5.1 服务接口

本站后端向固定受控 checker 地址发送 `POST /v1/check`，使用 `Authorization: Bearer` 服务鉴权。上游返回 `alive/dead/unknown`、reason、可省略的 providerCode、checkedAt、cached；固定版本已通过真实 loopback HTTP 验证。当前返回不含 provider HTTP 状态或响应结构质量，因此第 13 节的服务侧修复与样本资格是接入前置，本站不能只靠这六项判断可靠性。客户端仅提交链接／资源／条目 ID 和正整数版本，不可指定 URL、verdict 或服务地址。

用户报告沿 04 route；管理者手动检测拟用 `POST /api/patch/resource/link-check`，在服务端检查 owner／管理员权限；补链检测在保存事务提交后执行。站方资源盘归属沿 04，06 后再接 official 标记。新增响应保持 `private, no-store`，CSRF 不增加豁免。

### 5.2 顺序

资格与可见性预检 → 取得当前地址版本、证据轮次及目标状态 → 事务外有界检测 → 按 04 既定锁序锁内复核 → 保存用户报告（如有）、当前快照及允许的健康／事项转换 → 提交后缓存失效。

地址版本改变时，用户报告返回刷新提示，旧检测不写新版本快照；轮次或处理基点改变时，旧检测不能覆盖新裁决，按冲突／过期结果返回，不自动重试出站。被删除或隐藏的目标按角色重新校验。后到的弱观察不能回滚先完成的可靠失效。

可靠 broken 不依赖用户权重达到 3.0，也不通过改变用户票数来触发。报告资格仍须成立；冷却只是用户计权规则，不把明确机器事实改成有效用户票。重复请求与并发检测只转换一次，已经 broken 的链接不重复结案或发通知。只有实际存在的对应链接事项需要结案；无事项时留健康转换记录并通知归属方，不伪造空待办。调用 03 结案边界，不连带关闭资源级事项（D37）。

手动检测与补链检测现在更新机器快照；若取得可靠 broken 也可更新链接健康。补链保存成功后检测失败或发现新地址失效，都不能把已提交保存报成失败或回滚。对已有 broken 的 available 只展示事实，由有权限者明确恢复。

### 5.3 新鲜度、降级与缓存

直接判坏和建立机器冲突须使用本次新鲜、通过映射审核的检测结果；不能把上游默认 dead 七天缓存当成当前事实。本站使用专用 checker 实例，alive/dead/unknown 三个 TTL 均为 `0s`；M10-1 已验证重复请求均 `cached=false`、保留各次真实 checkedAt，改码不串用结果。正 TTL 的有码缓存串用已复现，不能启用。保留 provider 限流和单次总预算；若无法取得新鲜结果则降级 unknown，不绕过限流反复请求。

公开快照用于展示，不在后续报告中自动变成一份新检测证据。原始 checkedAt 不能被读取时间／写库时间替换。缺失、非法、明显未来或早于当前处理基点的时间不能用于改变健康。快照过期时间与展示提示由 W00 固定，UI 不因缓存读取自动触发检测。

服务鉴权失败、DNS／网络故障、限流、超时、无效 JSON 和不支持的主机都为 unknown。报告与补链继续完成；已有争议不退回七天路径。未知结果可记录本次尝试失败的事实，但不得伪造成功检测时间。

### 5.4 提取码：按 provider 实现需要传递（已定）

2026-10-08 用户要求以固定上游实现是否使用提取码为准：服务端已有合法保存的提取码且该 provider 的对应请求会使用时才传；不需要的 provider 不发送。不猜码、不暴力尝试，缺码／错误码或只证明分享存在而未验证取得条件时按已审映射给出有限结论，不能声称文件可完整下载。

| provider | 固定提交中的实际路径                                                             | 本站策略                                                           |
| -------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 夸克、UC | `quarkfamily.Check` 向 token API 发送 `passcode`，缺参数时读 URL 的 `pwd`        | 有合法提取码时按该路径传入；缺码按 provider 返回降级               |
| 百度     | `shorturlinfo` 不带码；`errno = -9` 时 `pageVerdict` 可把码作为 `pwd` 带到分享页 | 允许为上游回退路径提供码；仅进入提取码页不等于验证提取码或文件内容 |
| 和彩云   | `Check` 的码参数为 `_ string`，实际 `getOutLinkInfoV6` 只发 linkID 等字段        | 不发送码                                                           |
| 123 盘   | `share/get` 请求的 `SharePwd` 使用码，缺参数时读 URL 的 `pwd`                    | 有合法提取码时按该路径传；5103 必须结合语义，不能一律判失效        |

仅向自控 checker 和该 provider 的既定网盘端点传码，不传解压密码、用户 cookie 或本站登录 token；提取码不进入日志、公开结果或快照。判定用缓存禁用，或先证明缓存按真实码值安全隔离，不能直接使用上游只区分 `pc=0/1` 的缓存。升级上游版本时重查本表与样本，不沿用旧假设。

需要提取码的 provider，其检测基点还必须包含实际送检输入。码在请求期间变化时，旧回包不得覆盖新快照或改变健康；已有公开标签也应失去当前有效性。这个检查不把改码擅自改成“下载地址版本增加”，而是校验检测上下文；输入签名／码值只在服务端使用，不下发到公开 DTO。E10-01/03 增加同 URL 换码与回包交错、不同码不得串缓存的断言。

## 6. 界面与文件归属

- 后端 A：`app/api/patch/resource/link-check/*`、资源 get DTO、快照读写、04 报告／健康接线、校验、schema、迁移和后端测试。受控 checker 运维由后端 B 在独立目录处理，不并发编辑 A 的文件。
- 前端角色：`DownloadCard.tsx`、`ResourceDownload.tsx` 及既有报告／补链表单；每条镜像旁分别呈现“机器检测”“用户反馈”，冲突时有“有争议／待复核”说明。多镜像不能混用结果，390px 不溢出。
- 未获取地址的用户仍可看到脱敏的检测与反馈；真正地址、提取码及密码仍沿 access/restore 权限取得。
- 手动检测动作显示可能更新状态的确认说明，取消零写入；机器失败、过期回包、补链成功但检测失败分别反馈，不能把错误藏在绿色“正常”标签里。

## 8. 迁移、部署与回退

建议 04／05／10 同批验收和启用，部署按四步：

1. W00 同期完成参考评估与隔离 checker 部署：固定提交或镜像，验证 provider 样本、鉴权、限流、缓存和出口边界。不连接生产资源数据。
2. 04 稳定 ID、版本及健康合同到位后，由 A 接入网站，由前端接双重展示；使用真实 checker HTTP 服务、隔离 PostgreSQL／Redis 和独立网站构建完成 E2E。
3. 经具体生产操作授权后，先部署受控 checker 服务，验证健康检查与实际带鉴权的检测请求。单有 `/healthz` 成功不能证明业务可用；不启用全站扫描。
4. 按本站既有维护窗口完成备份、preflight、已审 sync、postflight、schema guard 和固定产物部署；再冒烟验证 04／05／10 的用户路径。服务运行与本站功能上线分别记账。

数据落点随 W00 固定，迁移由 A 统一交付；首次与有真实快照／报告后的重跑都要验证。生产不用 prisma db push，prisma:deploy-safe 也不是纯只读命令。新增服务配置仅限服务端，按项目部署规则同步示例与说明，不读出真实凭据。

checker 作为独立服务部署，优先使用与登录／身份服务分离的出网位置；容器隔离不等于出口 IP 隔离。服务 endpoint 只对本站授权调用，固定上游版本。实际机器、网络与运行方式由部署方案列明后执行，本轮未部署。

运行时 checker 故障走 unknown，不能清掉已记录的争议／失效。回退必须保留链接版本、已产生的健康结论、事项与快照兼容性，不回到删除重建链接的旧写入端。若上线前检测链未验收，不得把缺少 10 的发布标为此完整批次通过。

## 9. 测试与实验方案（完整验收待执行）

### E10-01 状态、冲突、版本与幂等

覆盖三触发 × 三态：可靠 broken 直接折叠；单条反馈 + available 同时展示且不驳回；达到阈值 + available 进入 disputed 并保留入口；unknown 按 04 进入或保持普通疑似。验证机器冲突超过七天、三十天或新增用户票时不会绕过人工复核；可靠机器失效、人工可用／失效、换地址能正确收尾。

在真实隔离 PostgreSQL 用可控交错验证：补链／删除／人工核实与检测回包竞争；较早观测晚到；并发 broken 只转换／结案／通知一次；已 broken 收到 available 不自动恢复；检测不写 grant/access 或获取计数，D37 资源事项不被连带关闭。

### E10-02 两层请求边界与故障

分别验证本站→固定 checker 服务的鉴权与目标限制，以及 checker→provider 的协议、主机、DNS／重定向、超时与响应体上限。分享 URL 不得成为内网代理；受控内部服务 endpoint 不与任意用户地址混用。任何失败不生成 broken，日志／响应不泄漏 URL、码、原始响应或认证信息。受控故障注入必须证明报告仍可保存、补链不被回滚。

### E10-03 样本、部署与公开展示 E2E

每个拟支持 provider 具备正常、删除／取消／过期、需登录／验证码／提取码、限流／反爬等具名样本，记录 raw status/reason/providerCode 到本站三态的映射。正常和不确定样本零误判 broken；不支持者 unknown。校验上游缓存禁用配置与真实 checkedAt，不能把陈旧缓存当作一次新检测。

真实浏览器→独立生产构建网站→实际 checker HTTP 服务→隔离数据库贯通。刷新和多个角色读取应看到同一链接的两类事实；进入争议后仍显示触发争议的近期反馈，不因轮次推进将展示人数归零；覆盖无记录、过期、失败、用户／机器冲突、多个镜像、旧版本结果隐藏、桌面／390px、操作取消、通知与脱敏。provider 传输用受控样本；有界真链抽查须先确定目标和授权。生产服务先行及网站启用分别留证。

### 13.3 评估发现的最小服务修复（交付见第 14 节）

1. **响应质量**：实际 UC/Quark detail `{}` 仍 alive，123 缺 code 仍 alive/0；HTTP 503 携 41004 仍 dead。这些与有效 tuple 相同，HTTP adapter 无法从现有结果补救。服务必须核对必要字段、成功结构与传输状态，429／5xx／失败跳转转 unknown，保留明确已审的 provider 403／404 JSON 情形。
2. **出站边界**：实际 stock UC 跟随合成 302 到 loopback；百度包装 client 会丢弃 CheckRedirect；123 接受任意子域／端口并出站到该 Host。需在 checker 校验 HTTPS、已批准 authority／默认端口、无 userinfo，并在实际 dial 绑定已验公网 IPv4／IPv6，复核每次跳转，保留百度的限制；网站输入校验或容器隔离不能代替。
3. **响应体与日志**：已有 1 MiB 上限、百度页面 512 KiB／预热 64 KiB，但截断前缀可能仍解析成功，应以 cap+1 拒绝超限。未知 provider 错误的 message/show_msg/desc 会进入日志，合成码 canary 已复现；删去原始文本，仅保留白名单状态与原因／必要安全 providerCode。上游 HTTP 响应没有 no-store，本站与受控 ingress 必须补齐。
