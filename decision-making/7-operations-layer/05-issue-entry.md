# 模块 05：入口分流（实施计划）

状态：设计待审，未实施。配对 PM 版：[05-issue-entry-pm.md](./05-issue-entry-pm.md)；总计划：[00-master-plan.md](./00-master-plan.md)（保留任务编号 M05-1 至 M05-5）；基线：[运营层设计基线](../7.operations-layer-redesign.md) 第 3.6、8.1 至 8.3、8.6 节。本文只写本模块的落点与它对模块 03、04 的接线契约，不代替这两份设计。源码事实与实施建议分列；本文未运行构建、测试、迁移或实验。

## 1 目标与基线

| 目标                                                       | 依据                     | 本模块交付                             |
| ---------------------------------------------------------- | ------------------------ | -------------------------------------- |
| 资源卡片底部只有一个「遇到问题」，先选目标再按现象分流     | 基线 3.6、8.2；M05-1     | 前台两步对话框与目标构造               |
| 每个现象只有一个去向                                       | 基线 8.2；M05-2          | 现象表常量、提交调用、无写入分支       |
| 环境类问题在求助区上线前给指南与后续说明，上线后换真实入口 | 基线 8.1、8.2；M05-3     | 检查清单、指南链接、可整段替换的临时段 |
| 条目页反馈收窄为三类，纠错投稿上线前不建代改队列           | 基线 3.6、第 6 节；M05-4 | 类型集收窄与说明文案                   |
| 入口内一句话受理范围与预计首次响应                         | 基线 8.6；M05-5          | 分支级提示文案                         |

## 2 偏离与理由

| 偏离                                 | 基线原文                                             | 本文做法                                                                                                                                                              | 理由                                                                                                                                                         |
| ------------------------------------ | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 第一步可选整条资源或某条链接         | 3.6 表把「遇到问题」的预填写为资源                   | 与 8.2 一致，第一步在链接与整条资源之间选                                                                                                                             | 8.2 明确「第一步选哪条链接或整条资源」；两节合并后以 8.2 为准，报告类现象必须落到具体链接                                                                    |
| 资源目标的违规举报需要 03 登记类型   | 3.3 违规举报的目标只列评论、评价、用户、小喇叭、求助 | 05 上线前置：模块 03 登记「违规举报 · 资源」类型，归站方、预计 3 天内首次响应，05 直接接入该类型                                                                      | 8.2 要求该现象去向举报，3.3 的目标清单漏了资源，属基线内部遗漏。最小接线是 03 补一行类型；降级成「其他」会改掉责任方与响应口径，在 05 另建举报后端更不可接受 |
| 纠错投稿上线前条目信息错误不提交事项 | 3.3 该类型「不进队列，界面直接引导转为纠错投稿」     | 上线前该分支只显示说明，不提交任何事项，不设例外                                                                                                                      | 纠错投稿未上线时照原文引导会落空；M05-4 已决定不建必须人工代改的纠错队列                                                                                     |
| 弱证据必须携带显式的网络确认         | 4.3「用户点『已尝试更换网络或加速器』后才写入」      | 界面先确认再提交，请求携带 `networkAcknowledged: true`，模块 04 对缺失与 `false` 一律拒绝                                                                             | 服务端无法证明用户真的换过网络，但可以要求这次确认存在且为真；不能因为「无法验证人」就省掉请求校验                                                           |
| 链接类提示不显示具体归属人           | 8.6 表写「资源发布者」                               | 统一写「该链接的归属方（资源盘链接为站方）」                                                                                                                          | 官方镜像上线前资源盘链接归站方（总计划 4.5），界面按发布者表述会误导用户                                                                                     |
| 超时说明按 03、04 的实际合同写       | 8.6「发布者超过 7 天未响应时，工单会自动转给站方」   | 发布者归属的链接写「达阈值进入疑似失效后 7 天无处理自动转为失效」；站方归属（资源盘／官方链接）写「没有自动超时，留在站方待办」；只有资源与描述不符类写「升级到站方」 | 7 天自动 `broken` 只适用于发布者归属的疑似失效，站方归属没有自动超时。照抄 8.6 既会承诺站方去修别人的链接，也会谎称官方链接会被自动判失效                    |

## 3 术语

| 术语         | 定义                                                                                  |
| ------------ | ------------------------------------------------------------------------------------- |
| 目标三元组   | `patchId + resourceId + linkId`，与现有揭示接口一致；报告类现象再附模块 04 的链接版本 |
| 现象         | 用户在第二步选择的可观察事实，不是分类标签                                            |
| 去向         | 现象的唯一处理路径：失效报告、工单、举报、指南、求助                                  |
| 临时去向     | 模块 07 或 08 未上线期间的替代显示，只有指南与说明，不产生任何记录                    |
| 网络提示确认 | 弱证据分支提交前必须点击的一次确认                                                    |
| 受理范围提示 | 分支内一句话：处理方与预计首次响应，对应当时已上线的能力                              |
| 快捷入口     | 链接旁的「报告失效」，由模块 04 交付，与本入口写同一投票                              |

## 4 数据模型

无新表、无新字段、无新索引与约束、无迁移脚本、无回填。本模块只读消费其他模块的数据与枚举：

| 来源                 | 05 需要的内容                                                                                                                                               | 缺失时的后果                                                                                                                                           |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 04（拟新增，硬前置） | 链接版本随资源读接口下发；原因标签枚举与权重；报告资格（30 天内揭示过当前版本，旧揭示记录不作资格）判定；弱证据缺 `networkAcknowledged` 或其为 `false` 即拒 | 前台拿不到版本时报告分支禁用并提示刷新，不得发不带版本的请求让服务端猜当前版本。版本与冷却证据的存储方案（D6）未定，不影响「必须携带版本」这一确定合同 |
| 03（拟新增，硬前置） | 事务类型枚举（资源与描述不符、资源发错条目、违规举报 · 资源、其他）、归属规则、发布者归属类事务的每日限额                                                   | 旧反馈与旧举报的新写入必须已由 03 切换完毕；未切换属前置验收未过，本批不再建第二条旧写入路径。类型缺失的现象只能显示为未开放                           |
| 07（后续）           | 求助创建入口与资源锚定                                                                                                                                      | 未上线期间用临时去向                                                                                                                                   |
| 08（后续）           | 修正提交入口                                                                                                                                                | 未上线期间用说明                                                                                                                                       |
| 现有                 | `PatchResourceLink.revealed` 只表示当前 24 小时展示态，用作中性提示，不等于报告资格；`resource.userId`、`resource.user.role` 仅用于展示分组                 | 无                                                                                                                                                     |

不作为任何判断依据的现有字段：资源与链接的 `updated`、`download`（下载统计以原生 SQL 累加，`updated` 也不能证明文件版本，见总计划第 2 节），以及揭示授权的 24 小时可见期（可见期与报告资格的 30 天揭示窗口是两件事，`restore` 只读、不产生揭示证据，新版本揭示不延长原授权）。

## 5 接口、校验、权限、幂等

### 5.1 分流矩阵

| 现象                                           | 目标       | 去向                                           | 提交端（属主模块） | 分支内提示                                                                                                                                                     |
| ---------------------------------------------- | ---------- | ---------------------------------------------- | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 网盘显示已删除、已过期、违规                   | 链接       | 失效报告（强）                                 | 04                 | 记一次投票；达阈值后由该链接的归属方处理，预计 7 天内首次响应。归属与超时口径见表下注                                                                          |
| 链接要求付费或与发布说明不符                   | 链接       | 失效报告（强）                                 | 04                 | 同上                                                                                                                                                           |
| 打不开、超时                                   | 链接       | 网络提示确认后写失效报告（弱）                 | 04                 | 先自查网络；仍要提交则同上                                                                                                                                     |
| 下载慢                                         | 链接或资源 | 下载相关问题解答，不写入                       | 无                 | 网络环境问题，不进任何队列                                                                                                                                     |
| 版本与描述不符、缺少声明的文件、内容与条目不符 | 资源       | 工单：资源与描述不符                           | 03                 | 归属按 03 的责任映射：官方资源归站方，普通发布者的资源即使已有官方镜像仍归发布者。预计 7 天内首次响应；发布者归属的事务超时未响应升级到站方。05 不另写归属判定 |
| 发在了错误的条目下                             | 资源       | 工单：资源发错条目                             | 03                 | 站方处理，预计 7 天内                                                                                                                                          |
| 压缩包损坏、解压失败、无法启动、乱码、存档问题 | 资源       | 07 前：检查清单与指南；07 后：锚定该资源的求助 | 07                 | 由社区回答，站方与发布者无回应义务；求助区上线后发布者会收到通知                                                                                               |
| 疑似违规或有害内容                             | 资源       | 违规举报（03 的「违规举报 · 资源」类型）       | 03                 | 站方处理，预计 3 天内首次响应                                                                                                                                  |
| 条目资料错误（条目页反馈）                     | 条目       | 08 前：只显示说明，不提交；08 后：提交修正     | 08                 | 08 上线前不进任何队列；上线后由站方审核修正，预计 7 天内首次响应                                                                                               |
| 其他（条目页反馈）                             | 条目       | 工单：其他                                     | 03                 | 站方处理，不承诺时限                                                                                                                                           |

提示写的是预计首次响应，不是处理完成时限，界面不出现「保证 X 天处理完」一类表述。

链接类分支的统一口径（在表下写一次，不在每行重复）：单条报告只是投票，达到 04 的阈值后才进入归属方处理；此后发布者归属的链接在疑似失效状态满 7 天无处理，由 04 自动转为失效；站方归属（资源盘／官方链接）没有自动超时，留在站方待办。归属与状态由服务端返回，界面不自行推断，也不因一次未达阈值的报告就宣称已经开出待办。

检查清单沿用 8.2：核对文件大小与校验码、重新下载。校验码一项只在对象存储链接上可执行（现状仅 `storage === 's3'` 展示校验码），其余链接的清单保留大小核对与重新下载，并链接下载指南与 RAR 修复教程。

### 5.2 校验与权限

- 客户端只做可用性收窄：未登录时展示入口与说明，提交时按现有方式引导登录，不新建鉴权逻辑。`link.revealed` 为假只给中性提示（当前没有可见的已获取链接，报告需要你获取过这条链接），不禁用提交：超过 24 小时展示期但 30 天内揭示过当前版本的用户仍有资格，由服务端最终判定。前台拿不到链接版本时才禁用报告分支并提示刷新页面。
- 权威校验全部在服务端：模块 04 判定登录、揭示资格、版本匹配、弱证据的 `networkAcknowledged` 是否为 `true`（缺失或 `false` 一律拒），以及按其当前版本与证据轮次定义的有效报告约束；模块 03 判定登录、目标存在与可见性、归属，以及发布者归属类事务的每用户每资源每日一条（该限额只适用于 03 为其定义了限额的类型，违规举报不套用）。05 不新增第三处校验，不替属主模块定表，也不把客户端判断当作授权。
- 目标合法性：三元组由所选卡片构造，`linkId` 只能来自该资源的链接列表，`resourceId` 只能来自当前条目的资源列表；服务端仍按 03/04 的归属与可见性复核，非法组合的错误文案由属主模块给出，05 只展示且不自动重试。
- 05 不新增 API 路由、schema、权限门槛与后台界面；条目页反馈的写入路径见 6.2。

### 5.3 幂等与并发

- 重复提交的正确性由属主模块的数据库原子约束保证：04 按其当前版本与证据轮次定义的有效报告唯一性、03 的「同目标同类型未结案唯一」。05 在请求期间禁用提交按钮，返回后刷新该资源，不用客户端去重代替数据库约束。
- 站内通知由属主模块在同一事务内对胜出动作发一次；不依赖 `createDedupMessage` 的先读后写做并发幂等（该 helper 无数据库级唯一保证）。
- 同一现象只调用一个提交端，禁止同时写报告与工单；「下载慢」与 07 前的环境类分支不产生任何写入，重复点击也不产生记录。

### 5.4 缓存

无新增读接口。提交成功后只刷新当前资源列表数据，写后失效沿用 03/04 的失效函数；条目页的 120 秒 ISR 不承载入口状态，入口与提示均在客户端渲染。

## 6 前后台界面及文件

### 6.1 交互

- 卡片底部按钮排在点赞与展开链接之后，桌面与移动端同一组件；对话框两步，可返回上一步，关闭不留草稿。
- 第一步列出该资源的全部链接（含模块 04 折叠的失效链接，标注「已失效」）与「整条资源」；单链接资源默认选中该链接，但仍显示当前所选目标。
- 第二步按目标类型给出现象；每个现象下方是一句话受理范围提示与去向说明；指南类现象只给链接，不出现提交按钮。
- 报告类现象复用模块 04 的报告提交组件，不复制原因标签文案与权重。
- 条目页反馈对话框收窄为三项单选：「其他」保留现有自由文本（沿用 10 至 5000 字限制），「资源发错条目」提示改到对应资源卡片提交并给出跳转，「条目信息错误」在纠错投稿上线前只显示说明。

### 6.3 后台

无新增页面、队列与权限；站方侧的展示与处理由模块 01、03、04 承担。

## 7 定时任务

无。阈值判定由 04 在报告事务内实时聚合，不靠周期扫描；04 的定时任务只处理疑似失效超时与争议收敛。本模块不注册任务，也不依赖 `withTaskLock`。

## 8 迁移与回填

- 无 DDL、无数据回填、无生产 SQL，不涉及 preflight/sync/postflight。
- 上线切换：入口与提示、常量、两篇指南文案随模块 04 同一批发布；发布后核对旧自由文本反馈不再产生站方待办。
- 回退边界：05 只有前台代码与文案，回退目标是模块 03 上线时的直接提交入口，或临时关闭分流按钮，不得恢复 03 之前的旧反馈创建端；模块 03、04 的读取与处理能力保持在线。已写入的报告与事务不随 05 回退，回退后仍需可处理。
- 文案记录随入口一起交付：完整受理范围正文不在本模块交付，只登记入口内提示的现行文本与被修订的两处指南句子。

## 9 测试与实验方案

### 9.1 单元测试（拟新增，纯逻辑）

`tests/unit/issue-triage.test.ts`：现象 → 去向与提交端映射的完备性（表中每行都有且只有一个去向）、目标三元组构造（`linkId` 必须属于所选资源）、报告类现象在缺版本时不构造请求、弱证据在未确认网络提示时不返回可提交状态、「下载慢」与临时去向返回无写入、常量替换为 07/08 已上线后临时文案消失。渲染层不引入新测试框架（沿用仓库现状，模块 01 的相关决定不阻塞本模块），界面验证在实验中手工完成，手工验收记录即为有效证据。

### 9.2 E05-01（未执行）：全部现象分支、目标携带与临时入口替换

- 目的：证明现象表逐项只有一个去向、目标不丢、无写入分支确实不写，且 07/08 上线后临时段可被整段替换。
- 前提与隔离环境：隔离数据库与隔离部署的 04 + 05 构建；测试数据含自定义链接、资源盘链接、模块 04 判为失效的链接、单链接资源与多链接资源；日期边界注入 now／假时钟，不改机器时间；替换验证用测试层替身注入 07/08 已上线的常量，只验证切换合同，不代表未来功能已通过。
- 关键步骤与数据组合：每个现象分支各走一例（共 10 例），报告类两例使用不处于冷却与争议、资格完整的普通样例；再补三个身份边界（访客、登录未揭示、只揭示过旧版本）与两个链接边界（资源盘链接、已失效链接），不做目标 × 现象 × 账号的全笛卡尔积；对映射函数跑 9.1 单测；注入替换常量后确认临时段消失且切换点唯一。
- 通过判据：每例只有一个去向；报告类请求携带 `patchId/resourceId/linkId` 与当前版本，弱证据另带 `networkAcknowledged: true`；在上述普通样例下强证据计 1.0、弱证据计 0.5（权重由 04 判定；04 因冷却或争议给出的合法零权重不算本实验失败）；下载慢与 07 前环境类无任何新增行；条目信息错误在 08 前无站方待办；注入替换常量后临时文案消失且没有第二处切换点。
- 失败判据：任一格丢失目标或版本；同时产生报告与工单；弱证据未确认即写入；无写入分支产生记录；替换后仍出现旧临时文案。
- 验证时间点：04 + 05 合批在隔离环境联调完成后、发布前。07、08 的真实替换随各自上线联调验收，本实验只验证切换合同，不代其宣称通过。
- 所需证据与清理：矩阵勾选表、报告与事务表行快照（脱敏）、单测输出、关键界面截图；隔离库数据用完回滚，不在生产账号留下报告。

### 9.3 E05-02（未执行）：非法目标、指南可达、受理范围与响应提示

- 目的：证明伪造与过期目标一律被服务端拒绝且不产生记录，指南可达，分支提示与当时真实能力一致。
- 前提与隔离环境：与 E05-01 同一隔离环境；准备跨条目资源、已删除资源、`status = 1` 的隐藏资源、旧版本链接与他人发布的资源。
- 关键步骤与数据组合：直接构造请求，逐项试 `resourceId` 不属于 `patchId`、`linkId` 不属于 `resourceId`、资源已删除或隐藏、链接版本过期、未登录、未揭示、访客身份，以及弱证据缺 `networkAcknowledged` 与其为 `false` 两种；正向对照一例有效的当前版本报告，并在该报告未达阈值时核对界面与通知只说明已记录报告，不宣称已开出待办或已开始超时计时；在界面上验证前台拿不到版本时不发请求、只提示刷新；验证「已过 24 小时展示期但 30 天内揭示过当前版本」的用户仍能提交；试同一用户对同一资源当日第二条发布者归属事务（只对 03 定义了日限额的类型，违规举报不套用）；确认旧反馈创建端不再产生新写入；逐条打开网站说明、下载相关问题解答、修复损坏 RAR、内容贡献指南四篇文档并核对入口引用文字；分别在发布者归属链接与资源盘／官方链接上核对提示差异，并核对官方资源与普通发布者资源在「资源与描述不符」分支的处理方差异；复查被修订的两句指南不再把资源问题引向评论区、Telegram 或邮件。
- 通过判据：非法组合、缺 `networkAcknowledged` 与 `networkAcknowledged: false` 全部被拒且无新增行，拒绝路径不产生 04 的系统证据、也不发 03 的通知；过期版本返回刷新提示，缺版本时前台不发请求；24 小时展示期与 30 天报告资格分离的正向用例可提交；有效的当前版本报告写入一条；旧创建端无新增；四篇指南可达且引用文字与页面标题一致；未达阈值的单条报告不宣称已开待办或已进入超时计时；达阈值后发布者归属链接写自动失效、站方归属链接写留在站方待办，两者都只承诺预计首次响应；未上线分支写明当前去向；05 引用到的流程里没有把资源处理引向私聊、评论区或邮箱的句子。
- 失败判据：任一非法目标被接受，或把缺失与 `false` 的网络确认当作有效；拒绝路径产生了证据或通知；缺版本时仍发出请求；合法的 30 天内报告被前台拦下；出现失效指南地址；提示承诺尚未上线的能力，把站方归属链接说成会自动判失效，或把链接超时说成转站方修复；05 流程仍把资源处理引向私聊或评论区。站点既有的联系方式与版权说明不在本项检查范围。
- 验证时间点：与 E05-01 同批，发布前完成；模块 07、08 上线时复核提示文本。
- 所需证据与清理：请求与响应记录（脱敏）、指南可达性清单、提示对照表、修订后的文案 diff；隔离库回滚。
