# 模块 05：入口分流（项目管理版）

状态：设计待审，未实施。配对实施计划（技术细节以它为准）：[05-issue-entry.md](./05-issue-entry.md)。总计划：[00-master-plan.md](./00-master-plan.md)（本模块任务编号 M05-1 至 M05-5）。产品依据：[运营层设计基线](../7.operations-layer-redesign.md) 第 3.6、8.1 至 8.3、8.6 节。

## 1 目标与责任人

目标：让用户在提交之前就把「资源出问题了」拆成四条去向——机制（失效报告投票）、责任（发布者的资源事务）、社区（下载与运行环境类求助）、站方（规则、放错条目、官方资源与官方链接、合法升级），站方不再逐条做人工分类与转达。判断标准是现象表每一分支都有唯一去向，且到达站方的只有工单与链接健康两模块定义为需站方处理的事项。

责任人：站长负责业务规则与上线后的运营验收；设计、实现与验证由实施方完成。本模块不新增角色、权限层级或协作方。

## 2 用户流程

1. 资源卡片底部只有一个「遇到问题」。
2. 第一步选目标：该卡片里的某条具体链接，或整条资源。
3. 第二步选现象。界面对每个现象给出唯一去向，并写明处理方与预计首次响应。
4. 网盘显示已删除、已过期、要求付费 → 记一次失效报告（强证据）。打不开、超时 → 先显示网络提示，用户确认已换过网络或加速器后才记录（弱证据）。下载慢 → 只给下载指南，不产生任何待办。
5. 版本与描述不符、缺少描述中声明的文件、内容与条目不符 → 交发布者处理；发在错误条目 → 交站方；疑似违规或有害内容 → 交站方。
6. 压缩包损坏、解压失败、无法启动、乱码、存档问题 → 求助区上线前显示检查清单与现有指南，并说明求助区上线后可直接在此提问；上线后换成携带该资源上下文的求助入口。
7. 条目页的「反馈」收窄为条目信息错误、资源发错条目、其他三项。纠错投稿上线前，条目信息错误只给说明、不提交任何事项，不建立由站方代改字段的队列。
8. 未登录用户能看到入口与说明，但提交需要登录；报告失效还需要近期获取过这条链接的当前版本，是否满足由系统判定，界面不提前拦下合规的报告。

## 3 本模块做与不做

| 做                                             | 不做                                         |
| ---------------------------------------------- | -------------------------------------------- |
| 选目标、选现象、唯一去向、分支提示与临时去向   | 失效报告、工单、求助、纠错投稿本身的处理能力 |
| 复用链接健康模块的报告提交与工单模块的事务提交 | 新增队列、后台视图、定时任务或新依赖         |
| 入口内一句话受理范围与预计首次响应             | 完整受理范围页正文（随站点文档统一编写）     |
| 与新入口冲突的两篇现有指南的最小文案修订       | 重写站内指南体系                             |

## 4 依赖与上线批次

- 硬前置：工单模块须先登记资源目标的违规举报类型，并完成旧反馈、旧举报写入的切换；链接健康模块须把链接版本下发到前台，并拒绝没有网络确认（或确认为否）的弱报告。任一前置未达成，这一批就不满足上线条件，不能靠砍掉必需分支来通过验收。这两处的服务端校验是唯一权威。
- 与链接健康模块同一批次发布（总计划第 3.3 节）。入口不得早于处理能力开放。
- 官方镜像上线之前，资源盘链接的归属方是站方，因此链接类提示统一写「该链接的归属方」，界面不判定具体是谁。
- 求助区上线时替换环境类临时去向，纠错投稿上线时替换条目信息错误分支；两处替换分别记在 M07-6、M08-5。

## 6 验收

1. 用完整现象表逐项走通：条目、资源、链接与链接版本这些目标不丢失。
2. 指南路径存在：网站说明、下载相关问题解答、压缩包修复教程、内容贡献指南四篇均可打开，检查清单与用户实际能看到的信息一致。
3. 提示中的处理方与预计首次响应对应当时已上线的能力，尚未上线的分支写明当前去向。
4. 本模块引用到的流程里没有把资源处理引向私聊、评论区或邮箱的句子，被修订的两篇指南复查通过；站点既有的联系方式与版权说明保持不动。
5. 与链接健康模块同批完成本地与隔离环境验证后再发布，上线后记录一轮真实使用结果。

## 7 风险与未决事项

- 费用与奖励整段仍待审定（D8）。本模块在求助区上线前不出现任何点数、悬赏或收费文案；桥接转求助的收费与资格、奖励资格不足的名额处理仍按 D8 定稿，本文不视为已批准。
- 资源级「疑似违规」不在基线违规举报的目标清单内，属基线内部遗漏。处理方式是让工单模块补登这一类型（站方处理、预计 3 天内首次响应），不把它降级成不承诺时限的「其他」。
- 弱证据的「已尝试更换网络」无法由服务端证明用户真的换过网络，但这次确认仍必须随请求提交，缺失即被拒绝。
- 基线受理范围页里「发布者超时未响应即转给站方」的概括与工单、链接健康两节不一致：单条报告只是投票，达到阈值后才进入归属方处理；此后发布者归属的链接满 7 天无处理自动判失效，站方归属的官方链接没有自动超时、只留在站方待办，只有资源与描述不符类才升级站方。分支提示按这两种归属分别写，并说明这是预计首次响应而不是处理完成时限。
- 现有下载指南与压缩包修复教程把资源问题引向评论区、Telegram 与邮件，与新入口冲突。本模块随入口修订这两处，完整规则正文仍随站点文档。
- 纠错投稿上线前，条目信息错误只给说明、不进任何队列；这一点已由本模块任务定下，不再另设例外。
