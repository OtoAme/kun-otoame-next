# 模块 07（PM 版）：求助区

状态：2026-10-28 站长重新审定范围，求助区先上线基础版，采用常见问答社区的做法；悬赏、自动关闭、社区验证、同问、与事项互转等自造规则移到上线后再迭代（第 7 节）。本文记录已定的基础版需求。基础版已在 `otoamegame/helpcorner` 分支实现，并于 2026-10-29 在隔离环境完成 E07-01～04 验收（第 9 节）；尚未合并、迁移生产或部署。技术契约见[实施计划](./07-help-zone.md)；上游为[总计划](./00-master-plan.md)第 4.8 节与[设计基线](../7.operations-layer-redesign.md)第 8.1、8.4、8.5 节。基线第 8.3 节与第 8.4 节中被本文替换的规则，以本文为准。

## 1. 目标与责任人

运行、下载、解压一类问题，以及求游戏、求资源，可以有地方发帖、让社区回答，而不是全部进站长收件箱或私信。站长不承担默认回答义务；站方只负责处理举报。

| 角色                        | 职责                                          |
| --------------------------- | --------------------------------------------- |
| 站长                        | 规则定稿、上线验收、上线后决定第 7 节的迭代项 |
| 站方（管理员，`role >= 3`） | 处理求助与回答的举报：确认违规或恢复          |
| 提问者                      | 发帖、编辑、采纳回答，满足条件时删帖          |
| 回答者                      | 回答、编辑自己的回答，满足条件时删除          |

## 2. 发帖：分类必选，关联可选

发帖时必须选一个分类，可以另外关联游戏或资源，但不强制。

| 分类         | 收什么                                                   | 不收什么                                                   |
| ------------ | -------------------------------------------------------- | ---------------------------------------------------------- |
| 求游戏或资源 | 求站内还没有的游戏、补丁、资料集，或站外的工具、字体等   | 无                                                         |
| 运行问题     | 区域语言、运行库、兼容性、显示字体、启动失败、乱码、存档 | 无                                                         |
| 下载与解压   | 网盘客户端、网络、分卷、校验、解压软件与密码格式         | 某条链接失效，请用链接旁的「报告失效」                     |
| 账号与站务   | 登录、验证、萌萌点规则、投稿流程等疑问                   | 需要站方改数据的请求，请用「问题处理」里的站务反馈         |
| 求推荐       | 求推荐游戏、找忘了名字的游戏                             | 已经知道是哪部游戏、想要下载或补丁的，发到「求游戏或资源」 |
| 其他         | 上述都不适用的社区问题                                   | 无                                                         |

关联有三种情况，发帖人和管理员以后都可以修改：

- 关联站内已有的游戏条目。
- 站内还没有条目时，只填一个游戏名，可以另附最多 5 个资料链接（VNDB、Bangumi、Steam、官网等），VNDB、Bangumi、Steam 链接会自动识别并标出编号，方便回答者确认是哪部游戏。帖子上显示「本站尚无此游戏」，并提示到工作台「我的条目」投稿这部游戏（普通用户和创作者通过投稿新增条目，只有超级管理员能直接创建）。
- 不关联任何游戏。

从资源卡片进入发帖时，会同时带上该资源；资源只是补充信息，可见性仍按它当前所属的条目判断。

发布前，系统按标题和关联的游戏列出相似求助，方便提问者先看看已有的回答。确认页说明「由社区自愿回答，不保证回应」，同时写明发帖费和发帖后的可用余额。

## 3. 回答与采纳

- 回答下面可以写回复（楼中楼，只有一层）。回复用来追问和补充，是纯文字，最多 1000 字；回答的「回复」按钮写给回答者，楼里每条回复下的「回复」写给那条回复的作者；对方和回答者会收到通知。回复带头像显示。回复不能被采纳，也没有「有用」。回答本身的链接规则与评论区一致：回答里可以直接写站外链接，包括网盘链接，不经过审核；站方通过举报和隐藏处理问题内容。
- 帖子和回答可以上传图片：编辑器工具栏「外链图片」旁边的「上传图片」把图片转成 AVIF 存到本站，并在光标处插入图片。限 JPG、PNG、WebP、AVIF，单张 8 MB 以内，每条内容最多 6 张。帖子正文的图片按较大尺寸显示，回答里的图片显示为小缩略图（高约 112px），避免回答占太多版面；点任一图片都会打开灯箱大图，整条求助的图片可以左右切换，支持缩放和下载。列表卡片右侧显示帖子正文里的第一张图作为缩略图，点击缩略图进入帖子；高度随卡片铺满（上下只留卡片内边距），图片居中裁切。卡片上的作者、游戏可以单独点击，分别打开个人主页和游戏页，点卡片其他位置打开帖子。上传后没有发布的图片会留在存储里，基础版不做清理。
- 站内提倡把资源发到条目的资源区，再把资源卡片的分享链接贴进回答。回答框旁边常驻一句提示：「分享游戏或补丁资源，建议先在条目资源区发布，审核通过后把资源卡片的分享链接贴到这里。」点击后打开对应条目的资源发布页。回答里的站内资源链接显示为资源卡片的标题，点进去就是条目资源区里的那张卡片，下载仍走资源卡片的现有权限与配额。
- 求助区自己不创建资源。资源只在条目资源区发布，仍按现行规则审核，官方镜像等后续流程也只作用于资源区的资源。
- 只有两种状态：「未解决」和「已解决」。帖子不会因为长时间没人回复而自动关闭，任何时候都能继续回答。
- 提问者可以采纳一条别人的回答，帖子随即变为「已解决」。之后可以改选另一条，也可以取消采纳，取消后帖子回到「未解决」。提问者自己的回答不能被采纳。
- 「有用」：登录用户对别人的回答各点一次，可以撤销。它只用于把回答排在前面，不发点数。
- 「关注此帖」：登录用户对别人的帖子点一次，可以撤销，点过后按钮显示「已关注此帖」，并显示关注人数，不另外开帖，也不收费。关注者在通知中心的「系统消息」里收到两类通知：有新回答时收到「您关注的求助「标题」有 N 条新回答」，只要这条还没读，之后的新回答只把 N 加一、不另发新通知，读过之后再有新回答才发新的一条；帖子变为已解决时另收一条「已解决」。楼中楼回复、改选或取消采纳不通知关注者，关注者自己的回答也不通知自己。

通知：

| 事件             | 通知谁                                             |
| ---------------- | -------------------------------------------------- |
| 有人回答         | 提问者（自答除外）                                 |
| 回答被采纳       | 被采纳的回答者                                     |
| 帖子变为已解决   | 关注了该帖的用户                                   |
| 有新回答         | 关注了该帖的用户（未读期间合并为一条，只更新数量） |
| 发帖时关联了资源 | 该资源当前的发布者                                 |

## 4. 编辑与删除

从用户角度看，帖子里可能写进了自己的系统环境、账号信息等，所以作者随时可以编辑自己的帖子和回答，去掉不想公开的内容。删除受下面的限制，因为别人已经花时间回答：

| 对象   | 谁可以删 | 条件                                     | 结果                                                         |
| ------ | -------- | ---------------------------------------- | ------------------------------------------------------------ |
| 求助帖 | 提问者   | 帖子没有别人的回答（自己的补充回答不算） | 帖子和其中的回答不再显示；发帖费不退                         |
| 求助帖 | 提问者   | 已有别人的回答                           | 不能删，可以编辑正文；确实需要删除（例如误贴隐私）时联系站方 |
| 回答   | 回答者   | 没有被采纳                               | 回答不再显示                                                 |
| 回答   | 回答者   | 已被采纳                                 | 不能删，可以编辑；提问者取消或改选后即可删                   |
| 回复   | 回复者   | 任何时候                                 | 回复不再显示                                                 |

已发出的采纳奖励不因删除或编辑收回。

## 5. 费用与奖励

| 规则     | 内容                                                                                                                                                                                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 发帖费   | 每帖 5 点，发布成功才扣，发布失败不扣；发布后删帖、被举报隐藏或没人回答都不退。可用余额不足 5 点时不能发帖，发帖页提示「余额不足，可先每日签到获得萌萌点」并给出签到入口；签到后（或当天已签到时）按钮变为不可点的「今日已签到」。新注册账号余额为 0，不另设免费额度 |
| 采纳奖励 | 一条帖子首次采纳一条合格回答时，系统给该回答者 3 点。每帖最多发一次；之后改选、取消都不转移、不收回                                                                                                                                                                  |
| 资格     | 提问者和回答者都要注册满 7 天，回答者的账号仍然存在。不合格时只记采纳，不发点数；这次不占用该帖的奖励名额，以后改选合格的回答时仍可发放                                                                                                                              |
| 每日限额 | 按上海时间的自然日计：每人最多发 3 帖，每人最多获得 3 次采纳奖励。当天已满时只记采纳，不发点数，也不占名额                                                                                                                                                           |
| 净效果   | 每帖系统至少回收 2 点（发帖费 5，最多奖励 3），自问自答绕不出点数                                                                                                                                                                                                    |

例子：小雨有 100 点，发帖后剩 95 点。小岚有 20 点，回答被采纳后变为 23 点。小雨之后改选小夏的回答，小岚仍是 23 点，小夏不得点数。

求助区不改变现有的资源发布奖励。回答里贴资源卡片链接不发额外奖励；回答者在条目资源区发布的资源，按现行资源规则获得奖励。

## 6. 举报、可见性与首页

举报：

- 登录用户可以举报别人的帖子或回答，进入站方的违规举报队列（03 的 `content_violation × help`）。
- 同一目标收到 3 名注册满 7 天、不同举报人的举报后，自动暂时隐藏。暂时隐藏不等于判定违规，举报仍在站方待办里。
- 站方的结论有三种：
  - 确认违规：保持隐藏并结案。
  - 判定不成立：恢复显示并结案，之前的举报不再触发隐藏。
  - 只给结论：目标没有被隐藏时使用，不改变内容状态。
- 隐藏和恢复都通知作者。整帖被隐藏时，提问者仍能看到自己的帖子，但其他人不能再回答。

可见性：列表、详情、相似求助、通知和首页一律由服务器过滤。规则如下：

- 隐藏和已删除的内容不显示。
- 关联游戏为 NSFW 的帖子，对没有开启 NSFW 的访客隐藏。
- 用户屏蔽的标签照常生效。
- 关联的条目或资源被删除后，帖子按「未关联」显示，不随之消失。

求助区列表可以按分类、状态、关联游戏筛选，按最新或「没有回答」排序。

首页：

- 入口：顶部导航加「求助区」；首页 Hero 卡片下方的导航按钮把「标签」换成「求助区」，标签页仍可从顶部导航进入。
- 布局：宽屏时求助区列表和详情右侧有侧边栏，放「发布求助」按钮与费用规则、分类导航（带各分类帖子数，计数随列表上方的「全部／未解决／已解决」切换）、登录后「我发布的」和「我关注的」：标题旁显示总数，各列出最近 3 条（标题一行，过长省略），右侧「查看全部」打开求助区列表的对应范围。向下滚动时侧边栏固定停在顶部、不跟着晃动，到正文末尾为止。手机上侧边栏排在内容下方，分类改用列表上方的下拉。侧边栏比窗口还高时（矮屏幕），不再固定，随页面一起滚动，避免底部内容看不到。
- 列表范围：登录后列表上方有「全部／我发布的／我关注的」标签，地址带 `?scope=`，可以直接分享或刷新。「我发布的」包括自己被举报隐藏的帖子；「我关注的」按公开规则显示，NSFW 与屏蔽标签照常生效。分类计数跟随当前范围和状态筛选。未登录访问 `?scope=` 会转到登录页。
- 面包屑：发布求助为「主页 › 求助区 › 发布求助」，详情为「主页 › 求助区 › 帖子标题」，编辑为「主页 › 求助区 › 帖子标题 › 编辑求助」。
- 「最新求助」与「最新评论」两个栏目在独立求助区上线后最后交付。
- 作者注册满 3 天的内容才进入首页聚合，普通列表与详情不受这条限制。
- 「最新评论」只取游戏条目评论，同一条目只显示最新一条。
- 栏目位置、条数和样式在后端就绪后再定。

## 8. 与其他模块的关系

## 9. 验收要证明什么

以下 E07-01～04 必须用隔离数据库和生产构建做真实验证，不能用 mock 代替。2026-10-29 已在提交 `7aced933` 的生产构建上执行 [验收脚本](../../tests/e2e/help-board.e2e.ts)，17 项检查连续 3 次全部通过，浏览器无页面错误，测试数据已清理：

| 编号   | 必须证明                                                                                                                                              |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| E07-01 | 六个分类和三种关联都能发帖；非法关联被服务器拒绝；关联对象删除后帖子按「未关联」显示；可见性过滤在所有公开面生效                                      |
| E07-02 | 发帖费、采纳奖励、每日限额、注册时长资格按第 5 节执行；重复提交只扣一次；并发采纳、改选、取消时奖励最多发一次，余额与账务明细一致                     |
| E07-03 | 编辑与删除按第 4 节的限制执行，与新回答并发时结果唯一；举报满 3 人自动隐藏，站方三种结论正确，旧举报不再触发                                          |
| E07-04 | 桌面和 390px 宽度的生产构建浏览器 E2E：发帖、回答、采纳、改选、删除、举报全流程；D40 入口仍可提交事项；旧首页不受影响。首页栏目 UI 最后交付时另行补测 |

验收环境与边界：

- 数据库是从开发库只导出结构、再按顺序执行求助区预检、同步、复检迁移的一次性 `help_accept_e2e`；Redis、服务端口（3180）都与其他工作区隔离，对象存储、邮件和外部请求未接真实服务。
- 只验证了桌面（1341px）和 390px 两种宽度、Chrome 一种浏览器。
- 「关联对象删除」只测了删除游戏条目；删除资源、重复条目合并没有单独测。
- 图片上传在另一个本机替身存储上手动验证过，未纳入该脚本。
- 首页「最新求助」「最新评论」栏目尚未实现，不在本次验收内。
