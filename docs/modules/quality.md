# 质量与交付边界

完成变更需要说明实际行为、验证结果和仍未验证的风险。测试数量或命令成功本身不能证明权限、账务、并发、界面和生产运行都正确。具体执行步骤归[测试指南](../project/testing.md)，事实与范围审阅归[审阅指南](../project/review.md)。

## 证据各能证明什么

| 证据 | 可支持的结论与边界 |
| --- | --- |
| 当前源码与针对性测试 | 支持静态规则、条件和预期分支；替身不能证明真实数据库、网络和浏览器。 |
| 一次性数据库与受控服务验收 | 支持该版本和样本下的真实事务、约束与失败处理；不能推断生产已安装。 |
| 浏览器观察 | 支持实际检查的视口和流程，不能推断所有页面均无溢出或可访问性问题。 |
| 构建与产物检查 | 支持构建及文件完整性，不等于目标服务器可运行或业务已上线。 |
| 目标环境验收 | 支持该环境、版本和配置的结果，不能自动沿用到新版本或不同流量。 |
| 文档机械检查 | 支持本地引用与格式，不能证明自然语言清楚或业务事实正确。 |

验证成本随改动风险安排。低影响文字或样式不需要新增复制实现的测试；行为修改优先针对性测试。共享设施、文件读取资产、迁移和发布需要相应更广验证，已通过且仍有效的结果不重复消耗。

## 文档与技能同步

每个代码提交后检查对应维护文档和技能；业务、权限、数据、缓存、上传、部署与验证流程改变时更新其主要文档，不复制相同事实。代码与文档技能分开提交；确实无需修改时，在交付或合并说明记录已检查及原因。

技能只保留用途、关键不变量和可点击的必读引用，详细步骤归文档。唯一来源是根目录 skills，工具发现目录通过链接共用；分工只在[技能索引](../../skills/README.md)维护。新增独立工作流才考虑新技能，不为子功能重复建立入口。

## 交付应能回答的问题

说明本次解决了什么、依据哪些来源、实际运行哪些检查、没有运行什么，以及失败会影响谁。未验证事项要绑定具体范围，不能把临时验收编号、历史压测或作者修改记录写进现行正文。没有可靠恢复依据时报告缺口，不能编造自动重试或补偿。

按[文档标准](../project/documentation.md)检查业务与操作任务可用性，处理完有证据的问题后停止。额外审阅与多模型协调服从当前用户授权，不是每个任务的固定成本。
