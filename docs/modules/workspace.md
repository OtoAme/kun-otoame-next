# 用户工作台与链接维护

工作台向所有登录用户开放，集中管理本人条目、资源和问题；没有贡献记录也能进入。它使用独立用户菜单，不加载管理员菜单与全站计数。管理员进入工作台后仍受本人范围限制，管理他人内容须使用受权后台入口。

工作台界面使用服务器确认的当前登录用户，问题处理的操作入口同时服从详情接口返回的能力字段。直接打开页面、刷新页面或浏览器中残留旧账号资料时，当前账号的操作入口和对话中的本人标记仍以这份服务器身份为准。

本文维护本人编辑与链接维护的规则。下载、反馈权重和健康结论由[业务规则](api-services.md)维护，文件和缓存由[数据一致性](data-cache-upload.md)维护，迁移步骤集中在[运维指南](operations.md)。

## 从哪里进入

| 入口                 | 用户可以完成的事                                                           |
| -------------------- | -------------------------------------------------------------------------- |
| 工作台首页与我的资源 | 查本人资源，按名称、状态和分区筛选，进入链接维护清单。                     |
| 我的条目             | 看本人投稿、审核反馈、名额、余额和已发布条目。复杂投稿编辑进入独立编辑页。 |
| 资源详情             | 编辑本人可编辑资源、上传或补链、回应维护及确认删除。                       |
| 问题处理             | 查看我提交的、待我处理的和我关注的问题，并进入本人有权读取的对话。         |

窄屏下，我的条目、我的资源和问题处理收在顶栏的导航菜单里，点按后从左侧展开，并标明当前页。宽屏下这三项直接排在顶栏同一行。个人主页要求登录后查看，继续展示正式贡献，本人通过资料卡中的「用户工作台」按钮进入私有管理；管理员另有「管理后台」按钮，两者各自保留。旧问题地址保留兼容跳转和合法的筛选、页码与选中项；历史通知仍可打开。打开问题只标记本人有权读取的相关通知，不能改变其他收件人的已读状态。

「我的资源」默认显示资源列表，链接维护在独立标签页中；切换标签页保留各自的筛选和页码。资源卡片以游戏封面和名称为主，同时展示资源名称、分类、状态、创建时间、链接数、链接使用的网盘或存储类型及待处理数，再通过卡片的编辑或查看入口进入详情。宽屏上封面按完整画面显示，不裁切。卡片边距保持紧凑。列表只带上网盘或存储类型，不带下载地址。备注在详情中阅读，加载失败与没有符合条件的结果分别提示。

## 管理投稿与已发布条目

条目与投稿卡片展示封面，图片无法读取时显示站点占位图。已发布条目提供「查看条目」入口；普通作者的修改申请尚未开放，可以进入条目页反馈更正。管理员继续使用条目页已有的编辑能力。

草稿和要求修改的投稿可以继续编辑，也可以从更多菜单删除；确认时显示这份投稿实际暂扣的金额。删除成功后清理对应浏览器草稿，并更新列表、名额和余额；后续列表刷新失败不恢复已删除的卡片。审核中的投稿只提供查看和撤回，撤回后才能继续修改或删除。已驳回、违规关闭的记录可以查看或从本人列表隐藏，隐藏不改变余额，也不清理浏览器草稿。名额、押金和审核结算规则见[投稿规则](api-services.md#内容发布与投稿)。

## 本人资源的编辑边界

身份取当前服务器会话，用户不能通过改请求选择另一个作者。普通作者只编辑正常资源；待审或封禁资源保留必要状态，不下发下载凭据。保存和删除在加锁后再次检查归属与状态，旧站点编辑入口也不能绕过。

可编辑外链会提供编辑所需地址、提取码等信息；普通作者对网站资源盘的受保护链接只看到保留该链接所需的引用，不取得保护内容。不可编辑资源同样不下发凭据。管理读取不创建下载授权、下载记录或失效反馈资格，不能把管理读取当成获取下载链接。

在地址框粘贴分享文案或带提取码的地址时，沿用前台的识别方式填入链接；识别出新提取码时替换原提取码并提示。该处理只发生在明确的粘贴动作，不在加载或普通输入时改写草稿，对象存储和其他只读链接不开放这项编辑。

普通作者不能改变、移除、重排或伪造受保护链接。服务器从数据库保留这些内容，不接受浏览器夹带的替换值。普通可编辑链接的保存会对照打开编辑时的完整链接集合和地址版本，而非只比较保存后留下的部分。

编辑失败或发生并发冲突时，界面保留尚未保存的内容，以及打开编辑时用于比较的原链接和地址版本，不自动取得新版本重试覆盖。提交前会检查整份资源，大小、分类等不合要求时指出具体字段和链接序号，并将焦点移到需要处理的位置；服务器仍独立校验。不可编辑的信息出现错误时保留只读限制，不通过开放字段解决。

保存成功、失败或冲突都会提示；失败和冲突的说明留在编辑页上。保存成功并取得最新详情后才更新这份比较记录，后台刷新不能擅自替换正在输入的草稿。如果保存已经成功、后续读取失败，界面明确说明内容已保存，提示通过「载入最新版本」核对。响应不完整、无法确认操作结果时会保留输入并提示核对，不直接宣称保存、删除或维护已经完成。投稿也有跨设备修订保护，保存冲突不自动合并。

需要放弃当前编辑并重新开始时，使用「载入最新版本」。点按后按钮显示正在载入，直到这次读取结束。有未保存修改或尚未提交的上传时，先确认；只有成功取得当前资源的最新详情，才替换草稿和比较记录。取消或读取失败都保留原输入。上传期间不能保存、整份删除或载入最新版本，保存期间也不能载入最新版本；旧请求不能覆盖新目标或新的编辑会话。

资源分类和存储选择复用前台表单规则。游戏类型与中文支持分别选择，类型改变时清除不适用的中文支持和平台；语言仍独立选择。类型、中文支持、语言和平台的可选项与前台相同，只列出当前分区和已选类型允许的平台。历史记录含有不再支持的选项时，提供明确的移除操作，保留仍有效的选择；打开页面和后台刷新不自动清理草稿。触屏滑动页面时，这些多选保持关闭，点按后才打开。上传入口按当前编辑中的分区判断，服务器仍核对真实上传权限和本人登记。对象存储文件的地址、大小和校验信息只读，外链不提供人工填写校验值的入口。

只有存在多条链接且当前链接允许移除时，才在该链接卡片右上角显示红色的移除图标。点按后需要确认；取消或关闭确认都不改变当前编辑。确认只从当前编辑中拿掉这条链接，已有链接要等保存后才真正删除。最后一条链接不能作为单链删除；整份资源删除统一在页脚确认，并遵守既有账务规则。网站资源盘另受保护限制。保存成功后的检测、缓存或清理失败不撤销已经提交的内容；自动检测没有完成时，提示会说明状态将稍后更新。

上传失败的说明留在对应上传位置，整份删除失败时保留确认弹窗。工作台接口发生服务故障时，提示中的参考编号可用于查找对应服务器日志。日志记录操作、结果、必要的账号和目标编号，以及失败字段的位置，不记录下载地址、提取码、解压码、上传凭据或原始请求内容；正常的列表读取不逐次输出成功日志。

## 维护如何开始和结束

单纯机器异常进入可选维护，不主动催办普通发布者。第一份符合资格、具有正权重且不是重复的用户报告，会共同保存报告、维护记录、参与人和首次通知。后续同轮报告合并，不重复催办；零权重或重复报告不能单独开启新轮。

| 发布者动作或情况 | 当前结果                                                                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 回应             | 发布者填写说明并提交后，这条维护记录显示为「已处理」。参与这次维护的反馈者会收到说明，操作者本人和已注销账号除外。网站显示的链接可用状态保持不变。 |
| 核实可用         | 仍需符合健康处理权限与间隔；链接可用状态的改变与本轮维护回应共同成功。                                                                             |
| 暂缓             | 只能选择 1 天或 3 天，期限内拒绝这条链接的失效反馈。                                                                                               |
| 暂缓到期         | 原记录回到待处理，不另建记录、不重新检测，也不重复催办。                                                                                           |
| 停止维护         | 必填说明，结束现有维护并停止当前地址版本的失效反馈；机器异常不会因此制造用户首报或结果通知。                                                       |
| 恢复维护         | 解除停止限制，不改变健康或地址版本；新的有效反馈才能开启新轮。                                                                                     |
| 更换地址         | 结束旧版本维护，新地址版本重新开放反馈。只改提取码等同版本内容不解除停止限制。                                                                     |
| 删除或移动资源   | 删除后退出维护清单并保留必要历史；移动保留原轮次和通知记录，更新目标。                                                                             |

停止和暂缓只限制这条链接的失效反馈，内容问题或违规举报仍可提交。服务器在出站检测前和报告保存到数据库时都复查限制，防止已经发出的请求绕过。网站资源盘由管理员处理。

维护清单保留资源信息与进入详情的入口；资源详情内只展示当前链接的维护信息和动作。回应、核实和停止的说明在对应确认弹窗中填写，暂缓弹窗选择天数，恢复维护只需确认。取消不发送操作，取消或失败后保留输入，失败原因显示在弹窗内。

每轮维护指从接受新的有效反馈到完成回应的过程。它与收集健康证据的轮次分别记录，不能把一边完成当作另一边完成。回应、暂缓、停止及历史接续不能擅自关闭健康事项，健康结案也不自动代表发布者已经回应。机器观察和用户反馈也可能改变健康，不能理解为只有人工核实才可改变。健康的 7 天与 30 天时钟不因暂缓重新计时。

## 待办、通知与公开范围

我的资源是链接维护的主要清单。待处理数包含可行动维护与原待处理问题，并排除已由维护记录代表的普通发布者链接问题，避免重复计数。未到期暂缓、可选维护、停止及已处理不计入；到期暂缓重新计入。尚未接续的历史问题保留入口与一次计数，站方争议、等待报告者和网站资源盘队列仍按各自规则处理。

维护首次通知进入作者的资源编辑详情，结果通知进入公开资源页。机器自动流转不反复催办普通作者；真实对话、管理员决定、争议或转交仍按受权参与关系通知。同一次变化同时结束维护和健康事项时，对同一个反馈者合并结果通知。

公众只看到失效反馈是否受限和何时恢复，不看到维护说明、参与者与内部对话。关联问题的可读性按原权限检查，看到维护项不代表获得完整对话权限。暂缓到期界面重新读取状态，不自动发送反馈。

资源按原官方与社区分组及平台、语言顺序展示，健康变化仅影响内部链接折叠；全部链接失效也不让整份资源消失。新读取或换地址后旧凭据失效，旧请求不能覆盖新状态；同次读取中的健康或维护更新分别合并，不清除有效凭据或未保存草稿。
