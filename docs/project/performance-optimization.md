# 当前性能策略与限制

OtoAme 通过静态页面、分层缓存、合并重复查询和批量入库，减少常见浏览请求对数据库的压力。这些策略各有适用范围：匿名公开页面可以共享结果，个人消息、账目、下载凭据和带偏好的内容需要按访问者读取。

本文描述当前仓库已实现的策略，不提供生产吞吐量保证。缓存配置、目标环境验收与故障排查见[日常运维](../modules/operations.md)，各类数据保存与刷新责任见[数据与缓存](../modules/data-cache-upload.md)。

## 静态首屏与按需读取

首页、游戏列表、标签和会社页面使用静态生成及定期重新生成。它们让多个访问者复用公开首屏，内容写入后还会请求主动刷新。

| 页面 | 当前重新生成间隔 |
| --- | --- |
| 首页 | 2 分钟。 |
| 游戏列表 | 3 分钟。 |
| 标签目录与详情 | 5 分钟。 |
| 会社目录 | 5 分钟。 |
| 会社详情 | 10 分钟。 |

这些间隔是页面配置，不是所有缓存层的统一新鲜度承诺。详情数据、匿名完整响应、浏览器和边缘缓存有各自的寿命与刷新条件。

首页首屏读取 24 条游戏和 4 份资源。正常首屏不再重复请求整份首页数据；空静态游戏数据才触发补充读取，空结果不会被保存成首页缓存。卡片另外读取实时浏览量和下载量，避免数字长期停留在静态快照。

标签详情先生成标签资料，游戏列表按访问者条件加载。会社详情可以复用默认不含成人内容的游戏列表；登录、成人内容偏好或屏蔽标签存在时，重新读取个性化结果。静态页面不能保存某个用户的筛选结果供其他人复用。

标签与会社详情默认各预生成关联数量最多的 50 项，数量可通过部署配置调整，也可关闭预生成。构建同时生成页面的并发上限为 2，以限制构建期间的数据库压力。标签和会社的页面内容与页面标题还会在同次渲染中复用读取结果。

## 查询结果与匿名响应缓存

Redis 缓存常见内容和列表查询。统一缓存读取会合并同一进程内相同的在途请求，并通过刷新锁减少多个实例同时回源。在允许短暂使用旧值的缓存中，读者可以先得到旧结果，后台再更新；冷缓存则等待持锁者或继续取得锁。Redis 异常时部分读取会直接查询数据源，因此缓存故障可能增加数据库负载。

首页兜底、标签和会社列表对匿名请求还缓存完整响应，减少重复查询与序列化。当前 Redis 和单进程内存各保留 30 秒，单进程内存最多保存 512 项；等价查询参数经过整理后可共用结果。登录、成人内容偏好和屏蔽标签请求绕过这一匿名完整响应缓存。

源站对可共享的匿名响应给出 30 秒共享缓存寿命，并允许在随后 5 分钟内先使用旧结果再刷新。个性化响应禁止缓存。多层缓存可能叠加，不能把某一层的 30 秒直接写成端到端最大陈旧时间。

写入后，应用按内容类别清理 Redis、请求页面重新生成，并清理相应边缘缓存。游戏与资源变更还会影响列表；会社关系变更同时影响会社页和游戏详情。详细刷新范围由[数据一致性说明](../modules/data-cache-upload.md#缓存何时刷新)维护。

## 实时统计与公开消息

游戏详情打开后的独立请求把浏览量写入 Redis 缓冲，后台任务每 2 分钟批量入库；读取时叠加尚未入库的数值。实时统计和浏览量写入响应不参与共享缓存。浏览量缓冲依赖 Redis，这条路径的失败不能用静态页面正常访问来证明没有影响。

小喇叭根据官方消息的生效与结束时间缩短缓存寿命，避免跨过已知展示边界继续使用旧结果。公开内容变更会推进独立的缓存版本，使后续读取不再使用旧版本结果；已经开始的请求仍可能返回其原快照。具体失败与时间边界见[数据与缓存](../modules/data-cache-upload.md#缓存何时刷新)。

## 并发与容量边界

当前部署配置使用三个应用实例，每个进程的数据库连接池最多 30 个连接。增加进程会增加潜在连接需求；维护脚本和其他服务也可能占用连接，不能只按单进程连接上限估计数据库容量。开发热更新会一并复用数据库客户端及其连接池，长期服务不逐请求断开连接。

消息、上传、投稿、下载和链接检测分别实施用户或访问者维度的限频，以保护查询、图片处理、存储与账务。不同操作在 Redis 故障时的处理不同，不能把它们统一解释为全站限流或抗攻击能力；限制与收费见[权限与业务规则](../modules/api-services.md)。

## 刷新与验证的实际限制

- 多进程内存缓存不能由另一个进程直接清空，仍可能短暂返回旧结果；已经在途的请求也可能按原快照完成。
- 缓存清理与数据库保存不是一个原子操作。内容保存后缓存清理失败，不撤销已经提交的内容，读者可能暂时看见旧结果。
- 应用支持 Cloudflare 清理，不证明目标站点已经配置了共享缓存。个人偏好、私有响应和页面框架的数据请求必须保持正确的绕过边界，游戏详情 HTML 不纳入当前公开白名单。
- 平台接受清理请求不等于读者已看到新内容。页面、图片和带不同查询条件的列表都需要在实际缓存节点检查。
- 本页没有可复用的当前生产容量实测。性能评估应分别观察匿名缓存命中、缓存未命中和个性化请求，并绑定应用版本、数据规模、实例数和错误情况。

数据库查找任务和索引变更风险见[数据库索引说明](database-indexes.md)。部署版本、反代配置和边缘规则都可能改变实际表现，不能把历史本机压测套用为当前生产能力。
