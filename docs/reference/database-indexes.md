# 数据库索引的职责与变更风险

数据库索引帮助系统按指定条件查找和排列记录。OtoAme 的索引服务于公开内容浏览、后台待办、个人历史和业务去重；它们不能单独证明网站具备某个吞吐量或响应时间。

本文说明当前数据结构中索引承担的任务。数据库中的实际安装情况需要另行核对，不能从仓库定义推断生产已经具备相同结构。结构变更的备份、执行顺序和回滚见[部署指南](../guides/deployment.md)与[数据库维护](../guides/operations.md)。

## 当前索引服务的查找任务

| 查找任务 | 当前支持与业务意义 |
| --- | --- |
| 发现与排列游戏 | 按内容分级结合发布时间、下载量、浏览量、收藏数、资源数、评论数或资源更新时间读取列表；类型、语言和平台支持多值筛选。 |
| 按标签或会社找游戏 | 关系索引支持从标签或会社定位关联条目；按关联数量排序的索引用于目录展示，别名索引用于搜索。会社身份解析按规范化值和旧别名原文分别查找。 |
| 评分排序 | 支持按平均评分、评分人数及条目关联读取，实际排序还受最低评分人数条件影响。 |
| 资源与链接管理 | 支持查找某游戏或某作者的资源、待审资源、资源内链接顺序以及到期健康处理对象。 |
| 下载资格与额度 | 支持查找个人或游客的资源授权、已获取镜像和时间范围内的获取记录。删除链接后仍保留必要的额度事实。 |
| 投稿与清理 | 支持按作者和状态找投稿、按提交时间找待审内容、外部编号查重，以及按时间取出待清理素材。 |
| 问题处理 | 支持按处理方、报告者、目标、状态和等待时间读取事项，并按顺序读取对话与关注记录。 |
| 后台统计与日志 | 支持按管理员和时间统计当日处理数、按时间倒序读取管理日志、按注册时间统计每日新用户，以及按日期统计每日登录人数。每日登录记录以「日期 + 用户」为主键，同一用户同一天只占一行。 |
| 萌萌点与公开消息 | 支持账户明细的稳定时间分页，以及小喇叭的公开列表、作者记录和官方生效区间查询。 |

这些是查询用途，不是完整定义清单。具体列组合、排序和数据关系以文末的数据结构链接为准，避免在文档中维护第二份易过时的索引定义。

## 唯一性也是业务边界

部分索引同时禁止重复数据，不能只因读取次数少而移除。例如，同一对用户只能建立一份私聊会话，同一游戏不能重复关联同一标签或会社；投稿创建、发放萌萌点、小喇叭发布和押金结算也通过各自的唯一性保证抵御重复请求。

外部编号的规则并不相同。Steam 商店页可能覆盖合集，因此允许多个条目共用；Bangumi、VNDB 的发行版本和 DLsite 编号仍受对应唯一性约束。会社规范化主名和可信外部身份要求唯一，但不同会社可以共享别名。共享别名需要业务层处理歧义，不能通过给全部别名加唯一限制消除。

未结事项的去重和发布者问题的每日提交限制各自使用可空的唯一标识。去重标识在事项结束时释放，记录本身保留；每日提交标识在当天一直占用，同一资源当天已结束的问题仍会阻止再次提交。修改空值的唯一性语义会改变能否创建新事项，必须作为业务规则变更审阅。

## 维护与变更的判断依据

索引是否有效，需要结合真实查询、数据分布和数据库执行计划判断。某次未使用索引，不能单独证明它无用；某条查询用了索引，也不能证明响应时间满足需求。公开列表、个人筛选和后台搜索应分别评估，缓存命中不能代替数据库查询验证。

索引占用存储，并增加相关写入与维护成本。添加前应核对已有定义、查询用途和生产实际结构，避免用不同名称重复创建相同索引。删除前需确认它是否承担主键、唯一性或低频管理任务；不能仅凭短期使用次数为零决定删除。

索引创建、替换和失败恢复可能受锁、表规模和数据库当前负载影响。应使用已经审阅的变更方案，在验证环境确认耗时、中断后的状态与恢复条件，再安排生产窗口；本文不提供可直接执行的临时建索引语句。

当前生产结构检查只接受没有差异，或一个经过数据库实际定义核实的发行日期索引识别差异。该特例不能扩展为忽略其他差异，也不能执行工具建议的重复重建来消除显示差异。具体检查与处理归[运维指南](../guides/operations.md#生产结构检查)维护。

## 结论的适用范围

当前仓库没有为所有查询提供可复用的生产执行计划或容量验收结果。本页不承诺固定查询毫秒数或网站请求量。性能判断需要绑定实际版本、数据规模、缓存状态和运行环境；当前已实现的应用策略见[性能策略与限制](../concepts/performance.md)。
