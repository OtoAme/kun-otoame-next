# 站点主题与颜色含义

用户可以分别选择站点配色和浅色或深色模式。前台、旧后台和管理员预览使用这套主题；工作台与新后台有独立的 shadcn 样式，只共享深浅色选择。调整某个前台颜色，不能据此推断控制台也会变化。

本文解释当前主题职责与维护要求，界面验收见[前端说明](modules/frontend-content.md)，修改与验证步骤见[开发指南](project/development.md)和[测试指南](project/testing.md)。

## 主题由哪几层组成

| 层次 | 负责什么 |
| --- | --- |
| 品牌配色 | 默认 Classic 与 Pink 的主色、强调色及焦点颜色，分别适配深浅色。 |
| 业务颜色 | 资源类型、语言、平台、内容分级、会社、推荐等级和评分等含义。 |
| 组件外观 | 首页介绍卡、轮播标题、私聊气泡、个人页等确需独立调整的外观。 |

统一颜色值由主题文件维护，再传给界面组件。组件使用含义明确的颜色，不逐处写死某个主题的色值。仅当业务含义确实需要独立控制时增加专属颜色，普通按钮、链接、标签、日志与用户状态继续沿用已有界面语义。

## 用户选择如何保持

浏览器保存的选择优先，页面保存的辅助凭据只用于无法读取浏览器存储时的回退。首次打开页面前应用主题，站内导航后再同步一次，避免静态页面恢复默认配色而选择控件仍显示 Pink。

首页与公开列表可以共用静态页面，不能为了读取个人主题把公开页改成每用户动态生成。硬刷新、服务重启后的首次访问、站内导航和过期辅助记录都要检查控件与实际配色一致。控制台与前台之间也要检查深浅色选择是否一致。

## 各类内容如何用色

Pink 的主操作和强调使用粉色系列，正常、平台和可公开内容使用淡蓝系列；资源类型采用淡紫到淡粉的背景、紫色文字与轻描边，语言、会社和成人分级使用相应淡粉系列。首页游戏卡片与详情头部的资源类型标签保持同样的浅底视觉，不因页面不同换成实心标签。

浅底标签与实心标签的文字需求不同，深色模式也需要单独文字色。渐变背景使用完整背景值，不能当作单一颜色套用；评分星星与卡片角标承担不同视觉职责，分开维护。推荐等级按强烈推荐、推荐、中立、不推荐和强烈不推荐区分，保持各页面语义一致；具体颜色定义由源码维护，正文不再复制颜色值。

私聊面板、本人和对方气泡、边框、主次文字、图片底色与回复高亮统一使用聊天主题颜色，两个站点配色继承同一组含义。只修一个气泡的深色文字容易遗漏其他状态，调整时需一起核对。

个人页的图标、文字链接和浅底按钮有不同颜色深浅，但均从同一品牌色派生。首页介绍卡和轮播标题使用系统宋体系列；字体回退不依赖远程字体下载。首页装饰图保留接入位置，当前默认不显示花朵，不能把空槽当成已有素材。

## 修改时的验收条件

新增主题应覆盖深浅色的品牌色与焦点，注册用户选项并引入主题文件；需要重新映射正常、警告或危险色时，同时维护对应界面桥接。业务和组件外观只覆盖确需变化的部分。具体步骤集中在[本地开发操作指南](project/development.md)。

验收时检查按钮、链接、焦点、标签、评分、个人页、首页卡片与轮播、私聊、只读预览及控制台隔离。文字、图标和焦点需要足够可见，错误和健康状态同时提供文字，不能只靠颜色区别。这些是设计与验收要求，当前文档不声称所有页面已完成对比度或浏览器验证。
